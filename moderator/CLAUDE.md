# Модератор — чат сервиса

Этот чат отвечает только за папку `moderator/`. Общие правила и контракт с порталом описаны в `../CLAUDE.md`, открытые задачи — в `../TRACK.md` → «Модератор».

## Что это

Модератор-бриф к официальному совещанию: повестка, участники по протокольному старшинству, сценарий, поручения, глоссарий, материалы. На выходе HTML по фирменному шаблону. Документы разбирает «Искра» (`app/llm_extract.py`).

- Адрес: https://workspace.example.ru/moderator/ (старый <наш домен> перенаправляет сюда).
- Стек: Python 3.12, FastAPI, SQLite `data/meetings.db` (совещание хранится JSON-документом), фронтенд на чистом JS (`static/app.js`), Quill и DOMPurify лежат локально.
- Вход и пользователи в портале. Здесь `app/portal.py`: пользователь из заголовков, описание действий для журнала (`_ACTIONS`), очередь отправки событий.
- Раскладка кода: `main.py` — вход, проверка пользователя, журнал, статика и подключение маршрутов; маршруты по разделам брифа — `routes_meetings.py` (совещание, шапка, архив, приём повестки, выгрузка), `routes_agenda.py` (повестка, докладчики, участники), `routes_content.py` (поручения, сценарий, глоссарий, приём тезисов во вступительное слово), `routes_materials.py`, `routes_iskra.py` (разбор документов, подсказка по людям); общие проверки — `deps.py`, схемы запросов — `schemas.py`. Новый маршрут кладём в свой раздел, а не в `main.py`.
- Журнал: `storage.save` кладёт сводку «было → стало» в `change_log` и в журнал портала. Новое изменяющее действие нужно добавить в `_ACTIONS`.
- Ответ «Искры» — это текст языковой модели, а не гарантированная структура: перед применением он проходит `llm_extract.check_schema` (документы) или `check_material_schema` (материалы). Новое поле в ответе нужно добавить и в схему, иначе оно будет отброшено.
- Все вызовы «Искры» (`llm_extract._call_iskra_raw`) — фоновые прогоны `POST /api/v1/runs` (с `Idempotency-Key`) и опрос `GET /api/v1/runs/{id}?after=N` с паузой 2→5 с, срок 14 мин общий на запрос (`DEADLINE`), по сроку/обрыву прогон снимается DELETE с учётом расхода; синхронный `/api/v1/chat` (90 с, 504) не используем, id файла одноразовый — `extract_with_file` на повторе грузит файл заново (05.10, `../CLAUDE.md` п. 5в).
- Загрузка файлов (умный разбор, «Приёмная», материалы к вопросам, файл с поручениями) принимает Word (.docx, .doc), Excel (.xlsx, .xls), PowerPoint (.pptx, .ppt), PDF, .rtf, .odt, .txt, .md, .csv, материалы — ещё и .html; формат по содержимому (`extract.problem`), чтение — `app/extract.py` на общем модуле `app/docs_common.py` (копия `portal/shared`, здесь не править; решение пользователя 05.10); в «Искру» файлом уходят только docx/pptx/pdf/txt/md, остальное — её текстом (`routes_iskra._for_iskra`).
- Сценарий хранится rich-текстом (Quill). Текст в редактор загружаем только через `_setQuillHtml` (`clipboard.dangerouslyPasteHTML`): присвоение `root.innerHTML` со списком Quill молча стирает. Правим `static/app.js` — поднимаем `?v=` у скрипта в `static/index.html`, иначе у людей останется старый.
- Типографика общая (`../CLAUDE.md` п. 5б): шрифт, размер основного текста и вид шапки карточки
  берём из `base.css`, своих не объявляем. Размеры внутри страницы — только в `rem` от общего
  базового, не в пикселях. Своего масштаба нет: «А− А+» — общие, в шапке рабочего пространства.
- Вкладок восемь — с «Результатами» после «Пакета» (02.10; вкладки «Первичка» нет с 01.10 — решение пользователя, как в «Повестке» 21.09: карточка
  «Вставить документ» с «Умным разбором (Искра)» — первая в «Повестке» и, с 02.10, в «Участниках», `_importCard`;
  неподтверждённый разбор после перерисовки показывается на обеих — `_hasImportCard`), и они держатся в одну строку: полоса листается вбок (`.tabs`), счётчик «2/6»
  живёт в подсказке, а не в подписи. Добавите вкладку — проверьте на 1024 px, что строка одна. С восьмой
  вкладкой боковой отступ `.tab` поджат 10 → 6 px: на 1024 px (Inter, база 14 px) полоса ≈ 587 px; колонка
  612 px, но с полосой прокрутки Windows (15–17 px, страница совещания всегда выше экрана) остаётся 591–593 px —
  при 7 px (≈ 603) не помещалось (ревьюер RC-2026-10-02-18, Н-6). Уже 1024 — листается вбок. Проверять в Chrome
  на Windows с полосой прокрутки, не только в Chromium без неё.
- Вкладка «Материалы»: выбранный файл сначала лежит в списке под вопросом (`_pendingFiles`, только на странице —
  сервер его разобрал на текст и ничего не хранит), пока человек не нажмёт «Разобрать Искрой»/«Сохранить как
  страницу». У каждого такого файла есть «Убрать» (`removePendingFile`, просьба пользователя 02.10): файл помечается
  `removed`, а не вырезается из массива — индексы в кнопках соседних файлов остаются верными; убранный файл не
  разбирается и не сохраняется.
- Совещание правят несколько человек сразу, поэтому: элементы списков адресуются стабильным `id` (не номером позиции), а длинные правки (шапка, блок сценария, материал) шлют `base` — значения на момент открытия формы. Расхождение — 409, интерфейс перечитывает данные и возвращает набранный текст. Кто ещё правит совещание — `storage.active_editors`, плашка в шапке.

### Материал к вопросу: окно разбора, диаграммы, поручения с галочками, вступительное слово

Решение пользователя 02.10. Вопреки п. 5а корневого `CLAUDE.md` («саммари доклада делает «Бриф»») разбор
материала «Совещание» делает само — по прямой просьбе пользователя, записано Оркестратором.
- **Разбор** `POST /api/meetings/{id}/materials/analyze` → `{result, warnings}`; ничего не сохраняет.
  `result` (`llm_extract.check_material_schema`): `type, question_num, speaker, title, text, intro` (1–2 предложения
  подводки), `summary` (подробное, абзацы и пункты «- »), `figures` (0–4), `theses` (3–4 по 20–25 слов),
  `conclusion` (1–2 предложения), `proposals` (1–4), `orders` `[{id, text, assignee, deadline}]`,
  `proposal` — старое поле: `compose_proposal` = вывод + «- » + предложения одной строкой (для блока
  «Предложение: …» сценария и старого кода). `warnings` — строки: отброшенные диаграммы, тезисов больше 4
  (лишние срезаны), тезис короче 12 или длиннее 30 слов (не режем), докладчик не из текста.
  `result.warnings` — прежний вид `[{name, field}]` по докладчику, для старого окна. Ответ прозой —
  повтор с `MATERIAL_STRICT_REMINDER`. Промпт `MATERIAL_PROMPT` опирается на правила тезисов
  (`../theses/docs/dnch-speechwriting-rules.md` §3, §9, §11, §14, §17, §43): цифры и сроки не выдумывать,
  срок поручения — только из текста. Поручений к материалу — не больше `ORDERS_MAX` (30), лишние срезаются
  с замечанием. **Подводка `intro` — «о чём вопрос», без обращения** («О подключении школ…», не «Прошу доложить
  о …»): так велит промпт, а `clean_intro` снимает ведущее «Прошу (также) доложить о/об» при разборе, `apply` и
  во входе `/opening` (ревьюер RC-2026-10-02-15, Н-2). Окно показывает верхние `warnings`, старый
  `result.warnings` — только если верхних нет (иначе докладчик предупреждался дважды).
- **Диаграммы** — `app/charts.py`: `svg(figure)` для `bar_h` (сравнение), `bar_v`/`line` (динамика), `donut`
  (доли); чистый Python, палитра брендбука, числа по-русски, тексты экранированы, `viewBox`, < 20 КБ.
  Интерфейс чистит svg DOMPurify — поэтому оформление только атрибутами: без `<style>`, `style=`, классов,
  `<defs>/<use>`, `<image>`, ссылок; `_sanitizeSvg` в `static/app.js` вырезает и атрибуты `style`, `class`,
  `filter`, `mask`, `clip-path`, `href`. Фигура: тип из четырёх, `items` — 2–12 пар `[подпись, число]`,
  числа конечные и по модулю меньше 10¹⁵; негодная отбрасывается с замечанием. **svg рисует только сервер** — из `items` при
  разборе, при `apply` (присланный svg не берём) и ещё раз в HTML документа (`_figures_html`). `id` фигурам
  (`f1…`) и поручениям (`o1…`) ставит сервер — по ним окно ставит галочки.
- **Применение** `POST …/materials/apply` `{result, filename}` — в `result` только отмеченные фигуры и
  поручения, тексты правленые. `Material` хранит `intro`, `text`, `figures` (со своим svg), `conclusion`,
  `proposals`, `proposal`, `orders` (тексты). Поручения → `Order(..., agenda_num, material_id)`; дубль по
  `_order_key` (регистр, ё, пробелы, кавычки, точка в конце) не заводим — ни с уже записанными, ни внутри пакета.
- **Удаление материала** уносит его блоки сценария и его поручения (`material_id`); ручные и чужие не трогает.
- **Правка** `PATCH …/materials/{id}`: каждое поле `MaterialUpdateIn` необязательное, `None` — не трогать
  (раньше правка без `intro` затирала подводку). **`proposal` у материала с выводом или предложениями всегда
  пересобирается** из них, присланное `proposal` не берётся (окно слало старую склейку — «Предложение: …» в
  сценарии не обновлялось, RC-2026-10-02-15, Н-1); окно поле «Предложение (из прежнего разбора)» показывает и
  шлёт только у материала без вывода и предложений. Подводка и «Предложение: …» в сценарии идут следом. `orders` (просьба пользователя 02.10: править поручения из материала)
  — список поручений этого материала целиком: совпавший `id` — правка text/assignee/deadline, без `id` —
  новое (`material_id`, `agenda_num` материала), нет в списке — удалить, пустой текст — пропуск. Поручения
  без `material_id` и других материалов не трогаются. Без `orders` поручения не меняются. Не больше 30 строк
  (иначе 422). **`base.orders`** — поручения материала `[{id, text, assignee, deadline}]` на момент открытия окна
  (`_materialBase`): если с тех пор их поправили, убрали или добавили — 409, как у других полей (Н-5).
- **Подводка первого вопроса — в его блок «Подводка»** (`reference`), как у остальных: `inject_material` больше
  не дописывает её в блок opening (вступительное слово собирает `/opening`, дописанная подводка ломала его список,
  Н-2). Пустой `reference` первому вопросу сценарий по-прежнему не заводит; если материал его положил, таймлайн его
  показывает, как у 2-го и далее. **У совещаний до 02.10** подводка первого вопроса уже лежит в тексте opening
  (`build_scenario` его сохраняет): если тот же текст (без разметки, регистра, пробелов и точки в конце) там есть,
  блок «Подводка» первому вопросу не заводится — иначе задвоение и +2 минуты (`_intro_in_opening`, RC-2026-10-02-18, Н-1).
- **Старому материалу дописали вывод или предложения** — прежнее «Предложение» (`proposal`, присланное или
  записанное) встаёт первым пунктом `proposals`, а не пропадает при пересборке (RC-2026-10-02-18, Н-2).
- **Старые записи** читаются через `models._known`: недостающие поля — по умолчанию, незнакомые (запись
  версии новее после отката) — пропускаются. Откат на код до 02.10 этого не умеет: `Material(**x)` упадёт на
  `figures`/`conclusion`/`proposals`, `Order(**x)` — на `material_id`; откатываться вместе с базой.
- **Вступительное слово** `POST /api/meetings/{id}/opening` (кнопка между «Сформировать модератор по повестке»
  и «Собрать заключительное слово»): вход `build_opening_input` — шапка и хронометраж (минуты блока opening ×
  `WORDS_PER_MINUTE` = 120, как в «Тезисах»), затем «Общие материалы» (без вопроса: название, тезисы, вывод),
  затем вопросы по порядку: формулировка, «Докладчики: ФИО, должность» в именительном (должность из повестки,
  иначе из участников), подводка и тезисы материалов. **Слово из вступительного слова не передаётся ни по
  одному вопросу** (решение Оркестратора 02.10): оно звучит целиком до первого вопроса, слово передают реплики
  сценария «по N вопросу прошу доложить …»; во вступлении докладчик только называется — «по второму вопросу
  доложит Кравцов Сергей Сергеевич, Министр просвещения», без «прошу доложить». Предложения и поручения не передаём —
  слово подводит к докладам, а не пересказывает их (§29, §32). `OPENING_PROMPT`; ответ режет `split_bullets`
  (предложение — пункт, строка — пункт, инициалы «А.А.» не рвут) и ложится текстом блока opening через
  `_bullets_html`. Нет материалов — 400 «Сначала разберите материалы…», Искру не зовём. Ответ — совещание.
  Если блок уже не пустой (руками или из «Тезисов»), интерфейс сначала спрашивает `confirmDialog` — прежний текст
  не вернуть (Н-9). `split_bullets` не рвёт «г.», «гг.», «ст.», «п.», «им.», «ул.», «т.е.» («тыс.», «млн» — рвёт:
  ими предложение кончается часто).
- **Расход Искры при неудаче** (`main.py`): запрос с ошибкой, но с потраченными токенами, тоже уходит в журнал
  портала одним событием с `tokens_in/out` (памятка §4), в `details` первой строкой «ошибка, код N – действие не
  выполнено»; без токенов ошибка, как раньше, не пишется.
- Заключительное слово (`build_closing_input`) берёт у материала вывод и предложения, у старых — `proposal`.

### Совещание — общая ось

Карточку совещания ведём мы, соседи своих не заводят (`../CLAUDE.md` п. 9, замысел — `../MEETING-SPEC.md`).

- `POST /api/meetings/find-or-create` — `{date, title, source}` → `{id, url, created, folder}`.
  Идемпотентно по паре «дата + название»: сравниваем приведённую дату (`normalize_date`)
  и название без регистра и лишних пробелов, архив тоже просматриваем. Поэтому дату
  **везде храним как ДД.ММ.ГГГГ** — иначе та же пара не найдётся и заведётся двойник.
- Файлы совещания ведут «Материалы»: у нас лежит только `folder` — id их папки
  (`PUT /api/meetings/{id}/folder`). Папку заводит интерфейс сразу после создания совещания
  и обновляет при смене даты или названия — `ensureFolder` в `static/app.js`, запрос идёт
  из браузера пользователя. Сервис может быть ещё не подключён: тогда молча живём дальше.
- **Папка пакета переезжает при смене даты/названия — id меняется** (ошибка на боевом 02.10,
  «Мероприятие не найдено»). id папки у «Материалов» — хэш её пути (`materials/app/tree.py::event_id`),
  `link` переносит папку (`materials/app/main.py::_relocate`) и отдаёт новый id по ключу совещания
  (`meeting.folder_of`), а у нас в `m.folder` мог остаться прежний (другая вкладка, другой сервис,
  несохранённый `PUT /folder`). Поэтому **все вызовы к пакету идут через `_withPackageFolder(m, fn, start)`**:
  карточка (`loadPackage` — и рамка вкладки «Пакет» строится по id, на который она ответила;
  `_foreignGenreDoc`, проверка перед «Скачать пакет», `refreshPackage`), `POST …/files` (`_fileToFolder` —
  ручная и автоотправка; `_materialToPackage` — материалы к вопросам), `…/title`. При 404 — одна перепривязка по ключу совещания (`ensureFolder` → `link`, `PUT /folder`),
  и если id сменился — повтор по новому; не сменился — исходная ошибка человеку. Новый прямой вызов
  к папке мимо `_withPackageFolder` не заводить. **Перепривязка (`_relinkFolder` → `_relinkFresh`) сначала
  перечитывает совещание с сервера** (`GET api/meetings/{id}`) и шлёт `link` с его датой, названием и `folder`,
  а не с совещанием этой вкладки: отставшая вкладка с прежней датой вернула бы папку назад (ревьюер
  RC-2026-10-02-28, Н-1). Сервер не ответил — не перепривязываем, человеку исходная ошибка. `saveHeader`
  дожидается `ensureFolder` **до** `refreshMeeting`, иначе обновление принесёт с сервера прежний id.
  **Новый id `ensureFolder` запоминает через `_rememberFolder`** — в переданном совещании, в открытом
  (`_currentMeeting`) и у вкладки «Пакет» (`_pkg.folder`), даже когда ему дали копию (`saveHeader` шлёт
  совещание с новой датой): иначе вкладка, которую уже открывали, строила рамку по прежнему id и писала
  «Папки этого совещания больше нет» (RC-2026-10-02-28, К-1). Тесты — `tests/js_package_folder_check.js`,
  `tests/js_package_embed_check.js` (7а–7в).
- **Человеку говорим «пакет совещания», а не «Материалы»** (решение пользователя 02.10: документы повестки
  и списка участников идут в пакет совещания). Ошибки — «Пакет совещания не принял документ: …»,
  «Пакет совещания недоступен: …»; сервис «Материалы» упоминается один раз — в подсказке вкладки «Пакет»
  и на кнопке «Открыть папку в «Материалах»» (это переход в сервис). Подсказка вкладки: «Пакет совещания —
  папка совещания; её хранит сервис «Материалы», и туда же попадают материалы к вопросам. Ниже — сама папка: …»
  (второго «та же папка, что в «Материалах»» нет, RC-2026-10-02-28, Н-6).
- «Пакет к совещанию» — это zip их папки; своей сборки пакета у нас нет и быть не должно.
- **«Собрать пакет»** на вкладке «Пакет» (решение пользователя 07.10: «кнопка собрать пакет, которая заберёт

  старшинству и её отключение вручную ведёт сам сервис, `participants_manual` — здесь не пересортировываем).
- Несверенный документ помечен в нём самом — тот же приём и тот же текст, что у документа ведущего
  (`_mark_unchecked`): первая строка красным жирным и колонтитул на каждой странице.
- Имя файла в пакете фиксированное, без даты — см. раздел ниже; при скачивании неопределённого
  документа отдельного «дата в имени» пути нет (agenda его тоже не заводил для пакета).

### «Повестка» и «Список участников»: скачать напрямую

Кнопки «Скачать .docx» на тех же вкладках, рядом с «Отправить в пакет» (`downloadAgendaDocx`,
`downloadParticipantsDocx` → общий `_downloadDoc` в `static/app.js`, просьба пользователя 29.09) —
независимое действие: человеку нужен документ, не обязательно кладя его в папку совещания.
Сверка ФИО перед выдачей та же и так же обязательна (сервер сам откажет 409, если она не пройдена —
`_downloadDoc` переспрашивает «Скачать без сверки?» тем же текстом, что и «Отправить в пакет»
«Скачать без сверки»), а несверенная редакция и здесь помечена в самом документе. Но в отличие от
`_sendDocToPackage`: без `_foreignGenreDoc` (папки совещания вообще не касаемся) и без debounce
автоотправки — прямое разовое скачивание по нажатию, в «Материалы» ничего не уходит. Имя файла на
сервере фиксированное без даты («Повестка.docx» — так «Материалы» узнают жанр при отправке в пакет),
для скачивания на свой компьютер дата добавляется на клиенте (`_withDate`): «Повестка_14.10.2026.docx»,
тем же порядком, что раньше показывал сервис «Повестка».

### «Повестка» и «Список участников» в пакет

Кнопки «Отправить в пакет» на вкладках «Повестка» и «Участники» (`sendAgendaToPackage`,
`sendParticipantsToPackage` в `static/app.js`) собирают документ и кладут его в папку совещания
тем же путём, что и «Модератор в Word»: `GET /api/meetings/{id}/export/agenda.docx` или
`…/export/participants.docx`, затем `POST /materials/api/events/{folder}/files` из браузера.
**С решения пользователя 28.09 это утверждённый Word-документ** (`app/agenda_docx.py`, перенос
вёрстки из сервиса «Повестка» — см. раздел ниже), не простой HTML: старые `export/agenda.html`/
`export/participants.html` (`app/exporter.py`) остаются на месте, ими по-прежнему можно
пользоваться отдельно, но кнопка и автоотправка шлют именно `.docx`. Имя файла фиксированное —
ровно «Повестка.docx» и «Список участников.docx»: по названию заголовка «Материалы» узнают жанр
документа и не приписывают название совещания (`materials/app/naming.py` → `role_of`/`opens_with`,
`materials/app/wording.py` → `WHOLE`). **`source.id` — свой у каждого документа
(`<совещание>-agenda`, `<совещание>-participants`), но это только наша, моdераторская защита
от того, чтобы повторная отправка одного документа заменила другой** (см. `_fileToFolder`):
«Материалы» само поле `source` нигде не читают (ревьюер RC-2026-09-28-6, К1) и различают
«Повестку»/«Список участников» только по жанру заголовка — тот же жанр и тем же способом узнаёт
и «Повестка» (сервис `agenda`), которая кладёт `Повестка_<дата>.docx`/`Список участников_<дата>.docx`
без `source`. Если в этом жанровом слоте уже лежит файл — «Материалы» кладут новую редакцию под
тем же именем и номером, старую уводят в «Архив» с датой, расширение рабочей копии следует за
присланным файлом (`materials/app/main.py::_new_version`, фикс 20ba8ef и `materials` 75c43bc —
документ больше не портится молча, как было раньше). Но пока сервис «Повестка» ещё работает
параллельно (шаги 2–3 переноса из `../TRACK.md` не сделаны), её документ должен оставаться
защищённым: молчаливая замена унесла бы более свежую редакцию, пока человек правит повестку
там, а не здесь (**решение Оркестратора Н1, ревьюер RC-2026-09-28-14**). Поэтому перед отправкой
`_sendDocToPackage` сам смотрит список файлов папки (`GET /materials/api/events/{folder}`) и не
шлёт документ туда, где в этом жанровом слоте уже лежит **чужой** (`_foreignGenreDoc(folder, hints,
docTitle)`) — предохранитель до тех пор, пока «Повестка» не закроется или «Материалы» не научатся
смотреть на `source` сами. «Свой/чужой» различаем по `origin` в карточке «Материалов»
(`materials/app/main.py::_card`, `store.origin` — имя, под которым документ прислали, `_ownOrigin`
в `static/app.js`): наш файл всегда без даты («Повестка.docx», и прежняя «Повестка.html» до
перехода на .docx 28.09 — тоже наша), у «Повестки» — с датой («Повестка_14.10.2026.docx»).
**Расширение больше не различитель**: с 28.09 «Повестка» тоже кладёт .docx, по формату файлы уже
не отличить. `origin` не пришёл (карточка без этого поля, файл положен мимо портала) — не знаем,
чей документ, и не блокируем, как раньше. Сверка ФИО — своя у каждого документа, не общая
с документом ведущего: у «Повестки» проверяются председатель и все докладчики (`people_flow.check_agenda`,
ровно то, что печатает `agenda_docx.build_agenda`), у «Списка участников» — все участники
(`people_flow.check_participants`), а не только докладчики, — иначе опечатку в госте без доклада
никто не заметит.

**Автоотправка, когда папка уже есть** (решение пользователя 28.09). Если у совещания уже есть
`m.folder`, кнопка — не единственный путь: `api()` замечает сохранённое изменение повестки или
участников (POST/PUT/DELETE по `/agenda…`, `/participants…`, а «Искра»-`/apply` — сразу оба
документа) и зовёт `_scheduleAutoPackage`, та откладывает отправку на `AUTO_PACKAGE_DELAY` (2,5 с)
и сбрасывает таймер при новой правке — debounce, а не на каждую букву, иначе быстрые правки нескольких
пунктов подряд завалили бы «Материалы» запросами. `_fireAutoPackage` держит не больше одной активной
отправки на документ: если предыдущая ещё не ответила, следующая ждёт ту же паузу, а не бежит поверх.
Сама отправка — тот же `_sendDocToPackage`, но с `auto: true`: без toast и без окон, вместо этого
функция возвращает статус (`ok`/`conflict`/`names`/`error`/`skip`), который превращается в значок у
вкладки «Пакет» (`_renderPackageBadge`) с причиной в подсказке — фоновая попытка не должна дёргать
человека, но и молчать про то, что документ не ушёл, тоже нельзя. Предохранитель «чужой документ
того же жанра» (`_foreignGenreDoc`) и обязательная сверка ФИО (`_checkNamesBeforeWord`) отрабатывают
и здесь: в фоне решение принять некому, поэтому при конфликте жанра, неотвеченном реестре, похожей
на опечатку или неизвестной записи — отправка просто не уходит, а не правится и не пропускается сама
(«close» не переименовываем и «unknown» не добавляем в реестр за человека). Кнопка «Отправить в
пакет» остаётся — способ отправить прямо сейчас, не дожидаясь паузы, и она по-прежнему говорит
toast'ом и окнами, как раньше.

### Люди: реестр портала, сверка ФИО, склонение

«ФИО → должность → ведомство» ведёт портал (`../CLAUDE.md` п. 5а), своего реестра у нас нет
(таблица `registry` в базе не пополняется, `names.json` не читается). Код — `app/people_flow.py`,
клиент портала — `portal.people_*`.
- **В реестр пишет только человек.** Разбор и импорт из «Повестки» реестр не меняют: отмечают
  людей (`portal.note_person`), спрашивают портал (`POST /internal/people`, `force: false` →
  new | differs | same) и ставят new/differs в очередь карточки `registry_pending`. Интерфейс
  показывает окно «Добавить в реестр?» с правкой полей; «Добавить» — из браузера под вошедшим
  (`POST /api/people` портала, адрес в `/api/me` → `people.add`), с `document` — из какого документа.
  **С сервера `force: true` не шлём никогда.**
- **Ручное добавление докладчика и участника — тем же путём** (решение пользователя 28.09).
  Основной способ — подсказка из реестра (`GET /api/names/resolve` → `searchSpeaker`/`addResolvedSpeaker`
  у докладчика повестки, `resolveName`/`addResolved` у участника): начал печатать фамилию, выбрал
  из списка — роль/ведомство приходят готовыми, реестр видит уже записанного человека и молчит.
  Свободный ввод («Или вручную» / «ФИО (или вручную)») никуда не делся — в реестре может не быть
  нужного человека, — но `add_agenda_speaker`/`add_participant` (`app/routes_agenda.py`) тоже зовут
  `portal.note_person` + `people_flow.queue_noted` перед сохранением: новый или расходящийся человек
  попадёт в ту же очередь `registry_pending` и то же окно «Добавить в реестр?», а не пройдёт тихо.
- **Сверка докладчиков сразу после разбора повестки** (просьба пользователя 02.10): Искра пишет
  докладчика так, как в тексте («Кравцов»), а в реестре он есть полностью и с должностью. После
  «Добавить»/«Внести отмеченное» для документа «повестка» интерфейс зовёт `people/check-agenda`
  (`_reconcileAgendaSpeakers`): `close` → окно «Докладчики и реестр людей» с «Заменить на …» (то же
  `_fixCloseNames`, что перед Word), `unknown` → окно «Добавить в реестр?» (если его ещё не показала
  очередь `registry_pending`). Короткую запись — одну фамилию или фамилию с именем — портал теперь
  отдаёт как `close` с полной записью (`portal/app/people.py::check`). `POST …/people/replace` принимает
  `role`: должность из реестра встаёт докладчику вопроса и участнику там, где пуста, заполненную руками
  не трогает; `old == new` — только дозаполнить должность, и если менять нечего, это 200 с `replaced: 0`,
  а не 409 (ревьюер RC-2026-10-02-1, Н2). Исправленное в окне «Добавить в реестр?» ФИО и должность тем же
  `replace` встают и в совещание (`_renameInMeeting`, с id совещания окна). Чтобы окно очереди и окно
  сверки не спорили (Н1): после применения разбора повестки `people_flow.drop_known_from_pending` убирает
  из `registry_pending` тех, на кого сверка отвечает `close` (их заменяют, а не добавляют), а
  `replace_name` при смене ФИО снимает старое имя с очереди (`resolve_pending`). `drop_known_from_pending`
  зовётся после разбора (`/apply`, `apply-changes`), ручного докладчика (`add_agenda_speaker`) и импорта из
  «Повестки» и сверяет ровно `agenda_names` — тот же набор, что `check-agenda`, поэтому ответ интерфейсу
  приходит из кэша `check_names`. После окна «Докладчики и реестр людей» интерфейс сверяет повестку заново
  (`_reconcileAgendaSpeakers`): за время окна совещание могло перерисоваться. Окно «Добавить в реестр?»
  помнит id совещания, для которого открыто: `pending/resolve` и `replace` уходят в него, не в текущее.
- **Карточка «Вставить документ» и перерисовка «Повестки».** Признак «Искра разбирает» — `_smartBusyFor[id
  совещания]` (`_smartBusy(id)`), а не `btn.disabled`: перерисовка (`renderMeeting`) пересоздаёт кнопку, второй разбор
  того же совещания при этом не запускается, новой кнопке возвращается вид «Искра разбирает…»; в другом совещании
  кнопка свободна (ревьюер RC-2026-10-02-3, Н-1). При старте разбора на месте результата — карточка «Разбираю
  документ…» (`#smart-progress`), прежняя карточка ошибки с «Повторить разбор» не висит; кончился без результата —
  убирается. Короткая просьба со слов («Добавь вопрос Кравцова…») — правило 15 системного промпта: повестка с одним
  вопросом, только JSON; ответ прозой → вторая попытка со `STRICT_REMINDER` (`llm_extract.extract`).
- **Искра в «Повестке» одна** (решение пользователя 02.10): отдельного поля «Добавить вопрос с Искрой» нет,
  всё — через карточку «Вставить документ или попросить Искру». `smartImport` сам выбирает путь
  (`_isAgendaCommand`): пустая повестка, файл, длинный или многострочный текст → `/api/analyze` (разбор с нуля
  или список изменений); короткая просьба со слов в непустую повестку → `/agenda/command` (тот же путь, что было
  поле: докладчик из реестра, позиция «первым»), затем сверка докладчика с реестром; Искра команду не поняла →
  обычный разбор тем же текстом. Команда — это повелительный глагол добавления («добавь/добавить», «внеси»,
  «включи», «запиши», «вставь», «впиши») **и** слово «вопрос» в первой строке, до 3 строк и 300 знаков; фрагменты
  документа («Внесение изменений…», «Вопрос о…», «Доклад …») и просьбы изменить существующее («поставь …») —
  не команда, `/agenda/command` умеет только добавлять (ревьюер RC-2026-10-02-4, Н-2). После успешной команды
  старый неподтверждённый разбор сбрасывается; если за время команды сменили совещание, toast говорит, что и куда
  добавлено (повтор задвоил бы вопрос). `_smartBtnReset(meetingId)` зовётся с id во всех трёх точках —
  `smartImport`, `reanalyze`, `uploadFile`; без id признак «разбирает» залипал (RC-2026-10-02-4, К-1). Галочки списка изменений живут в `_pendingChanges[i].checked`
  (`_updateChangesCount`), перерисовка рисует выбор человека. Невставленный текст `#imp-text` и прокрутка
  переживают перерисовку того же совещания (ревьюер RC-2026-10-01-1, Н1).
- **Сверка перед Word.** `POST /api/meetings/{id}/people/check` → `/internal/people/check` по ФИО
  докладчиков в именительном. `close` — окно «Кадошников П.А. — в реестре Кадочников П.А.» с заменой
  одним нажатием (`people/replace`: повестка, участники, сценарий, фразы пересклоняются); сервер
  тоже не отдаёт `export.docx` при `close` (409). `unknown` — предупреждение и окно «Добавить в реестр?».
  **У сверки свой вызов**: таймаут `CHECK_TIMEOUT` 4 с, общую паузу после отказа она не соблюдает
  и не включает — медленный фоновый поиск должности её не отключает (ревьюер RC-2026-09-21-6, К1).
  Реестр не ответил на сверку — выгрузка отвечает 409 `X-Names-Check: unavailable`, интерфейс
  спрашивает «Выгрузить без сверки?», и только с флагом `?unchecked=1` (в журнале — «выгружено без
  сверки ФИО (реестр не ответил, флаг unchecked)»: прямая ссылка тоже его ставит). **Несверенный
  документ помечен в нём самом** («ФИО не сверены с реестром людей» — первая строка и колонтитул Word,
  плашка в HTML, «(ФИО не сверены)» в имени) и **в папку «Материалов» не кладётся** — только
  скачивается: сверенную редакцию в папке он не заменяет.
  **Сверка общая для Word и HTML** (`routes_meetings._names_checked`): HTML-бриф — тоже документ.
  Кэш сверки сбрасывается при «Заменить» и после «Добавить» в реестр.
- **Склонение ФИО — только `app/names_common.py`** (копия из `portal/shared`, здесь не править):
  `accusative()` для «прошу доложить кого?», `genitive()` внутри `_initials_genitive`. Своего нет.
  Старые фразы сценария с прежним склонением («Павела») `Meeting.refresh_speaker_phrases`
  пересклоняет при выгрузке и замене ФИО.

### Точечная правка повестки/участников Искрой — список изменений с галочками

`app/agenda_changes.py`, `POST /api/meetings/{mid}/agenda/apply-changes` — решение пользователя
28.09, перенос **по образцу, не дословно**, из сервиса «Повестка» (`agenda/app/changes.py`,
`../agenda/` со временем закроют). Раньше правка через «Искру» для непустой повестки была
только «Дополнить» (безопасно, но только добавляет) или «Заменить целиком»
(`llm_extract.apply_to_meeting(replace=True)`) — полная замена стирала материалы, поручения
и сценарий, привязанные к номерам вопросов. **Опасное поведение в коде «Заменить целиком» не
переписано** — `replace=True` по-прежнему стирает раздел целиком; кнопку не убрали, а сузили
до случая, где стирать нечего: пустого раздела. Интерфейс поэтому предлагает её, только когда
раздел пуст (`existingCount === 0` в `renderSmartResult`); это ограничение было только на
клиенте, обходилось вкладкой со старым скриптом — по замечанию ревьюера RC-2026-09-28-14 (Н3)
`POST /api/meetings/{id}/apply` тоже отказывает `replace=True` на непустой повестке/участниках (409).
Для непустой повестки/участников
`/api/analyze` теперь дополнительно считает список изменений (`_with_diff` в
`app/routes_iskra.py`, ключ `changes` в ответе — `None`, если раздел пуст или тип документа не
«повестка»/«участники») и интерфейс (`static/app.js` → `_changesHtml`/`applyChanges`) показывает
его вместо «Заменить целиком»: галочки на конкретных пунктах, а не «всё или ничего».
- «Искра» по-прежнему возвращает состояние целиком (ей так проще и надёжнее) — список изменений
  считает сервер, сравнивая с тем, что есть сейчас: «добавить вопрос», «заменить докладчика по
  вопросу N», «убрать участника Х». **Удаления по умолчанию не отмечены** — Искра могла просто
  не упомянуть пункт, а не иметь в виду его убрать; замена уже заполненного поля (должность,
  ведомство) — тоже не отмечена, заполнение пустого — отмечено.
- Каждое изменение помнит, что было на момент предложения (`was`), и вносится только если это
  всё ещё так (`still_valid`) — иначе чужая или более поздняя правка не затирается. **Без
  отдельного счётчика `rev`, в отличие от `agenda`**: у совещания и так нет глобальной версии
  (правки идут по стабильным `id` и точечным 409, как везде в сервисе), а `still_valid` по
  каждой операции точнее, чем «что-то в совещании изменилось — значит, конфликт у всех».
  Если что-то из отмеченного устарело — 409 `{message, applicable: [id...], stale: [{id,label}]}`
  без `force`; с `force: true` вносится только применимое, остальное — в `skipped` ответа.
- Докладчик у «Модератора» — не объект со своим id (`Speaker` у `agenda`), а параллельные списки
  (`AgendaItem.speakers`/`speaker_roles`/`speaker_minutes`); внутри вопроса они адресуются именем
  (как и остальной код повестки, `deps.speaker_pos`), не отдельным ключом.
- Убрать вопрос по галочке — вместе с ним каскадно убираются его материалы, поручения и блоки
  сценария (как `cascade=true` у ручного удаления, `remove_agenda`): иначе после пересчёта
  номеров (`renumber_agenda`) они молча повисли бы на чужом, переименованном вопросе. **`still_valid`
  для `remove_question` сверяет не только формулировку, но и слепок id этих материалов/поручений/
  блоков сценария на момент предложения** (`was_materials`/`was_orders`/`was_scenario`): формулировка
  могла не измениться, а коллега за это время положить к вопросу материал (например, «Бриф» прислал
  саммари доклада) — без сверки каскад унёс бы его молча, без 409 (ревьюер RC-2026-09-28-14, К1).
- После применённых изменений — один `renumber_agenda` и один `sync_agenda_participants` на весь
  пакет (не на каждую операцию), и та же очередь «Добавить в реестр?», что у ручного добавления
  и импорта (`portal.note_person` + `people_flow.queue_noted`) — см. раздел «Люди» ниже.
- «Заменить целиком» остаётся доступной только когда раздел пуст (`existingCount === 0` в
  `renderSmartResult`) — там разбирать нечего, «Дополнить» и список изменений не нужны.

### Скорость: соседи не должны тормозить сервис (SRE 21.09, GET совещания шёл 10–12 с)

  по умолчанию и спросим в следующий раз. Бюджет — **на весь запрос** (`_budget_left`), не на вызов.

### «Повестка» → «Или добавьте вручную»: докладчик из реестра

Решение пользователя 02.10: поле «Докладчик» с подсказками реестра людей по мере ввода (`agendaSpeakerInput`, пауза
`SPEAKER_SUGGEST_DELAY` 250 мс, `api/names/resolve`, ответ на устаревший ввод отбрасывается); выбор кликом или Enter
(↑/↓ — по списку) кладёт чип «ФИО – должность из реестра»; докладчиков несколько — чипов несколько (`_newSpeakers`,
по совещанию, переживают перерисовку). Свободный ввод можно — последним пунктом подсказки «добавить как есть», чип
помечен «нет в реестре»; Enter, пока подсказок к этому вводу нет, мимо реестра не добавляет: пауза не кончилась —
ищет сразу, запрос уже ушёл — ждёт его ответа (`_spkSuggest.inflight`/`shownFor`), дальше человек выбирает. `addAgenda` шлёт
`speakers` и `speaker_roles` (должности из реестра); напечатанное, но не выбранное, — тоже докладчиком, как раньше.
Был свободный ввод — после добавления `_reconcileAgendaSpeakers(id, только вписанные в этот вопрос)` (похожая
запись — «Заменить на …», неизвестный — окно «Добавить в реестр?»); прежних неизвестных, от которых человек уже
отказался, не предлагает (RC-2026-10-02-20, Н-3). Сервер `POST /agenda` не менялся (сверка в нём прогревала бы кэш и звала реестр на
каждое добавление).

### Что приезжает из других сервисов

- «Повестка» → `POST /api/meetings/import-from-agenda`: повестка, участники и шапка.
- «Тезисы» → `POST /api/meetings/{id}/scenario/opening-from-theses`: строки тезисов ложатся
  во вступительное слово сценария (`<ul><li>` по строке), `minutes` — время чтения, `0` не трогает текущее.
  Текст заменяется целиком, прежний виден в журнале портала.
- «Транскрибатор» → `POST /api/meetings/{id}/results`: транскрипция, саммари, проект протокольных решений во
  вкладку «Результаты» (раздел выше); совещание он находит через `find-or-create`.

Все эти запросы приходят из браузера пользователя тем же доменом (`credentials: same-origin`):
пользователь и права обычные, из заголовков портала, общих секретов между сервисами нет.

## Работа

```bash
.venv/bin/python -m pytest -q                      # тесты: портал и Искра подменены
bash ../portal/scripts/dev_stack.sh                # интерфейс через портал: http://127.0.0.1:8080/moderator/
ops/deploy.sh                                      # выкладка на ПК (сначала отметка в ../TRACK.md)
```

Сам по себе сервис без портала не открывается, для проверки в браузере нужен стенд. Локальная `data/meetings.db` содержит тестовые данные, продуктивная база лежит только на ПК.

## Нельзя

- Возвращать собственный вход или проверку владельца совещания: все видят всё.
- Делать абсолютные адреса `/api/...` и `/static/...` в интерфейсе.
- Останавливать процессы по шаблону без `--port 8765`.
- Трогать `../portal`, `../brief`, VPS, туннель и задачи планировщика, кроме `ModeratorServer` и `ModeratorBackup`.
