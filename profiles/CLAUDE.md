# Объективки — чат сервиса

Этот чат отвечает только за папку `profiles/`. Общие правила и контракт с порталом — в `../CLAUDE.md`,
задачи — в `../TRACK.md` → «Объективки».

## Что это

Объективка — краткая официальная справка о человеке на одну страницу A4: фото, ФИО, должность,
ключевые данные, полномочия, образование, опыт работы, награды (решение пользователя 05.10).

Два способа сделать объективку:

1. **По имени.** Человек пишет «Кравцов Сергей Сергеевич» и по желанию подсказку (должность,
   ведомство — чтобы не спутать однофамильцев). «Искра» ищет в открытых источниках — только
   официальных и надёжных (сайты ведомств, Госдумы, вузов, официальные биографии) — и возвращает
   сведения по схеме и источники со ссылками (refs), как «Тезисы» без материалов.
2. **По справке.** Человек прикладывает документ о человеке — любой типовой файл: Word (.docx, .doc),
   Excel (.xlsx, .xls), PDF, PowerPoint (.pptx, .ppt), .rtf, .odt, .txt, .md, .csv. «Искра» достаёт
   те же поля только из текста справки, без интернета; источник — «справка». Переключатель
   «дополнить из открытых источников» — недостающее «Искра» ищет и помечает ссылкой у каждого
   пункта. Фото — первая картинка документа Word (.doc/.rtf/.odt сперва переводятся в .docx).

Файлы во всех трёх формах («по справке», пакет, объединение) принимаются **как в «Брифе»** (решение
пользователя 07.10: «везде однообразие»): пунктирная рамка «Перетащите … сюда / или нажмите, чтобы
выбрать файл» с подписью про типы, файлы можно бросить и на любое место страницы (рамку легко
промахнуть), приложенное показано строками (значок типа, имя, размер, «Убрать» / «Другая справка»),
не тот тип — понятная ошибка до отправки. Код: `dropZoneHtml`/`wireDrop`/`takeFiles` в `static/app.js`,
стили `.drop`/`.doc` в `static/style.css`; поле `<input type="file">` скрыто за рамкой. Файл, брошенный
на страницу без открытой формы: картинка на карточке — фото, один документ — «Новая объективка»,
несколько — «Переработать и объединить». Проверка — `tests/js_drop_check.js`.

Плюс две сборки одним файлом:

- **«Объединить объективки»** — из реестра (отметить несколько) и/или прикреплённые .docx объективок:
  первая страница — содержание по фамилиям («1. Кравцов Сергей Сергеевич …… 2»), строки — внутренние
  гиперссылки Word на закладку в начале каждой объективки, дальше каждая с новой страницы. Порядок
  меняется (↑/↓, перетаскивание), «Убрать». 2–10 объективок.
- **«Переработать и объединить»** (пакет, дополнение пользователя 05.10) — до 10 произвольных
  документов о людях («кривые» объективки в любом виде): по каждому — карточка в реестре по нашей
  форме (путь «по справке»), список результатов с предупреждениями (не нашлось ФИО, не уложилась
  в страницу, файл не читается), порядок, один файл в нашем формате. Карточки правятся по отдельности,
  «Пересобрать файл» собирает заново.

Готовое — «Скачать Word» и «Приложить к мероприятию» (у одной объективки и у объединённого файла).

## Место в портале

- id `profiles`, адрес `/profiles/`, порт **8990** на 127.0.0.1 (на стенде 8991), `/healthz`.
- Папка сервиса — переменная `PROFILES_HOME` (портал знает её по своему `.env`): в ней `.env`,
  `data/profiles.db` и файлы. Без переменной — сама папка `profiles/`.
- **Ключ «Искры»** сервис не хранит и маршрута для него не имеет: портал пишет `ISKRA_API_KEY`
  в `<PROFILES_HOME>/.env` (как «Тезисам» и «Транскрибатору»), сервис читает его при каждом вызове.
- Регистрацию в портале, nginx, порт в выкладке, `sync_shared.sh`, запись на доске делает общий трек.

## Чтение файлов (решение пользователя 05.10, общий модуль `docs_common.py`)

Поля «по справке» и «Переработать и объединить» принимают `docs_common.ACCEPT`: .docx, .doc, .xlsx, .xls,
.pdf, .pptx, .ppt, .rtf, .odt, .txt, .md, .csv (браузер получает строку в `/api/me` → `accept`). Формат —
по содержимому, не по расширению. docx/pptx/xlsx — своими силами (у xlsx — текст ячеек по листам, ячейки
строки через табуляцию); .doc/.ppt/.xls/.rtf/.odt — через `soffice --headless --convert-to` (временный
профиль, срок, снятие группы процессов, одна конвертация за раз); PDF — pdftotext, иначе PyMuPDF, иначе
понятная ошибка. Битый файл (в том числе испорченный поток deflate внутри целого zip) — понятная 400.
Объединение принимает .docx, .doc, .rtf, .odt (переводятся в .docx); PDF — отказ «Объединяются документы Word».
Модуль правится только в `portal/shared`, копию раскладывает `sync_shared.sh`.

Защита от враждебных файлов (ревью RC-2026-10-05-4) — в самом модуле: пределы на вход, число записей,
сумму и каждую часть zip (размер — до чтения, чтение потоковое с обрывом); XML — линейным проходом по
тегам без регулярок с откатом, срок разбора 10 с; LibreOffice — без сети (профиль запрещает внешние
ссылки, прокси в никуда); мусор вместо текста — отказ. Сервис добавляет своё: справка, где меньше
20 знаков текста, «Искре» не уходит; фото из docx ищется тем же линейным проходом с пределами.

## Сведения объективки (`model.py`)

`fio`, `birth_date`, `birth_place`, `position`, `organization`, `category` (deputy | official | scientist | other),
`key_facts [{label, value, src}]` (фракция, регионы, комитет / ведомство, классный чин / степень, звание),
`powers [{text, src}]`, `education [{year, text, src}]`, `career [{period, text, src}]` (по возрастанию лет),
`awards [{year, text, src}]`, `photo_url` (только ссылкой — сами ничего не скачиваем), `refs [{name, url, about}]`,
`note`. `src` у пункта — «справка» или ссылка; в Word не идёт. Ссылки — только http(s).

## Как ищет «Искра» (`iskra.py`)

Правила — по образцу `theses/app/iskra.py`: машинный запрос без навыков и документов, без вопросов;
ничего не выдумывать, чего нет — пусто, сомнительное — не писать, а отметить в `note`; русский язык;
кратко, чтобы уложиться в страницу A4 (опыт работы до 12–15 строк, награды — главные).
По имени — источники только официальные и надёжные, энциклопедии и агрегаторы — лишь чтобы найти
официальный; каждый факт — с источником в refs и ссылкой в src. Однофамильцы без подсказки — пустые
поля и список найденных в `note`. По справке — только текст документа; ссылки «Искры», если она их
всё же дала, отбрасываются. Справка + интернет — сначала справка, недостающее — с источниками.

Чтение файла, сборка объединения и сверка ФИО идут в отдельном потоке (`run_in_threadpool`): событийный
цикл свободен, `/healthz` и запросы других людей отвечают, даже когда портал или LibreOffice медлят
(ревью RC-2026-10-05-2, Н-2). Сверка — с тайм-аутом 5 с, у объединения — одним запросом на все ФИО.

Схему «Искра» может не принять — повтор без `strict`, потом без схемы (формат проверяет `parse_json`).
Вопрос «Искры» (`interaction_required`) — прогон снимается, человеку: «уточните подсказку». Срок — 12 мин.
Расход — в журнал при любом исходе (успех, ошибка, отмена: брошенный прогон снимается DELETE и его
расход забирается). Пока «Искра» собирает, правка карточки отклоняется (409) — ответ не затрёт правку.

## Сборка Word (`docx_build.py`) — своим кодом

Выбор: **свой код (zip + XML), не python-docx.** Причины: объединение переносит тела готовых файлов
на уровне XML (приём «Брифа»), и ему нужна оболочка документа — те же части, из которых собирается
одиночная объективка: один способ сборки на оба пути; ширины колонок в twips и фото в EMU задаются
точно, без шаблона-файла. python-docx остаётся тестам — независимой проверкой, что файл читается.

Вёрстка: A4, Times New Roman, поля верх/низ 2 см, лево 3 см, право 1,5 см (с образцов). Шапка —
таблица без границ: слева фото (ширина 4 см, высота по пропорции, не выше 5 см; строка с картинкой
одинарная), справа ФИО жирным (кегль +2), должность, «Родился/Родилась …», ключевые данные. Без фото
колонки нет. Ниже: «Полномочия:» → «Образование:» (год – заведение) → «Опыт работы:» (таблица
период | – | должность, колонки 1800/340/7215 twips — доли образца 1951/356/7724 в ширину поля) →
«Награды, почётные звания, поощрения:». Пустые разделы не выводятся. Кегль и шрифт — в каждом прогоне.

**Одна страница.** Высота считается при сборке: перенос по словам с ширинами букв Times New Roman
(`count_lines`), высота строки 1,15 кегля × интервал, отступы абзацев, высота фото. Лестница
`LADDER`: 14/1,15 → 13/1,15 → 12/1,15 → 12/1,0 — берётся первая, где высота ≤ 95 % поля. Оценка
сверена с раскладкой LibreOffice (шрифт с метриками Times New Roman): расхождение ±5 %, тест
`test_уложенная_объективка_в_раскладке_одна_страница`. Не уложилась и на 12/1,0 — документ всё равно
собирается, на экране: «Объективка не укладывается в одну страницу — сократите «Опыт работы» или …».

## Объединение (`merge.py`)

Объективки из реестра собираются заново и идут тем же путём, что прикреплённые файлы: тело переносится
как есть. Взято из «Брифа» (копия функций, не импорт): поля Word, кроме внутренних, снимаются
(INCLUDEPICTURE «\\\\сервер\\…», DDE, INCLUDETEXT наружу не тянут, видимое остаётся), ссылки — только
http(s)/mailto, картинки, стили, списки и закладки переименовываются, разметка страницы файла снимается.
Отличия: объективка узнаётся по ФИО в первой непустой строке (в том числе в ячейке шапки после фото,
как в образцах), номера рисунков `wp:docPr` сквозные, новая страница — крошечный абзац с
`pageBreakBefore` (1 пт) с закладкой `_P<n>`: абзац с одним разрывом оставил бы пустую строку наверху и
мог вытолкнуть объективку на вторую страницу. Содержание: `w:hyperlink w:anchor="_P<n>"` + поле
`PAGEREF _P<n> \h` с готовым числом (Word уточнит по F9; updateFields не ставим). Номер страницы —
длина объективки из реестра (подбор страницы) или оценка чужого файла по его разметке (кегль,
интервалы, таблицы, картинки, явные разрывы) — на образцах совпала с раскладкой.
Чужой файл — понятная причина («не похож на объективку: в первой строке нет ФИО»), а не 500.
Враждебный, но правильно оформленный XML (ревью RC-2026-10-05-8, Н-2): элементы (`w:sectPr`, `w:style`,
`w:num`, `w:abstractNum`) выбираются линейным `_spans`, а не `.*?` (на самозакрывающихся тегах это
было квадратично), связи и атрибуты — линейным разбором общего модуля, у токенов полей самозакрывающиеся
варианты идут первыми и `.*?` не перескакивает через такой же тег, вложенность полей — не глубже 50,
закладки переименовываются одним проходом, принадлежность абзаца таблице — бинарным поиском.
Тест: по 20–50 тысяч каждого такого элемента — объединение или отказ быстрее 2 с. Карточка
из реестра идёт в содержание со своим ФИО как есть, по виду его не проверяем (иностранец латиницей,
«Иванов И. И. (род. 1970)» — ревью Н-4).

## Маршруты

```
GET  /healthz                         без входа
GET  /                                страница
GET  /api/me                          кто я, can_edit, адреса соседей, есть ли ключ «Искры», пределы
GET  /api/profiles?scope=&q=&archived=  реестр: mine | team | all (X-Portal-Team), поиск по фамилии/должности
GET  /api/search?q=&limit=            общий поиск портала
POST /api/profiles {fio, hint, key}   по имени → фоновый сбор
POST /api/profiles/from-doc           multipart file, web, hint, key → по справке
GET  /api/profiles/{id}               карточка + состояние сбора
PUT  /api/profiles/{id} {data, rev}   правка с версией (409 — изменили / идёт сбор)
POST /api/profiles/{id}/iskra {replace}   собрать заново (409 needs_replace, если сведения есть)
POST /api/profiles/{id}/cancel        отменить сбор
DELETE /api/profiles/{id}             «Удалить» — в архив;  POST …/restore — вернуть
                                      (у архивной нельзя собрать Word, сменить фото, отдать в пакет, включить в объединение)
DELETE /api/profiles/{id}/permanent   стереть навсегда — только администратор
GET|PUT|DELETE /api/profiles/{id}/photo   фото (JPEG/PNG до 10 МБ)
POST /api/profiles/{id}/build         «Пересобрать Word»: подбор страницы + сверка ФИО
GET  /api/profiles/{id}/docx          «Скачать Word» (устарел — пересобирается)
POST /api/profiles/{id}/name-ok {fio} ФИО расходится с реестром людей — «это другой человек»
POST /api/profiles/{id}/meeting       запомнить мероприятие (после «Приложить к мероприятию»)
POST /api/merge                       multipart order=[{kind:profile,id}|{kind:file,index}], files, title, batch
GET  /api/merges/{id}  · GET …/docx · POST …/meeting
POST /api/batches                     multipart files (1–10), web, key → пакет
GET  /api/batches · GET /api/batches/{id} · PUT /api/batches/{id}/order {profiles}
```

Только администратору: `DELETE /api/profiles/[^/]+/permanent` — строка для `ADMIN_WRITE_PATHS`
портала. Остальные изменяющие — сотруднику; администратор документы не ведёт (сервис тоже отклоняет),
`chief` — только просмотр.

расходящееся с реестром людей», «Объективка приложена к мероприятию», «Объединены объективки»,
«Пакетная переработка объективок», «Объективка удалена (в архив)», «… восстановлена», «… удалена навсегда».

## Сверка ФИО с реестром людей (контракт п. 5а) и исключение «Это другой человек»

Перед выводом в документ (сборка, скачивание, объединение) ФИО уходит в `/internal/people/check`.

- `exact` — документ выходит.
- `close` — в документ не выпускается. На экране оба написания рядом («В реестре: Кравцова Светлана
  Сергеевна — директор, школа № 5 / В объективке: Кравцов Сергей Сергевич»), первой кнопкой «Заменить на «…»».
- **Исключение для объективок (ревью RC-2026-10-05-2, решение Оркестратора 05.10; в п. 5а корневого
  `CLAUDE.md` его записывает общий трек — другим сервисам это не прецедент):** кнопка «Это другой
  человек…». Объективку часто готовят на человека, которого в реестре нет, а однофамилец или тёзка
  с похожим отчеством для неё обычен; без кнопки пришлось бы искажать ФИО под реестр или добавлять
  непроверенного человека. Условия: нажатие — только через подтверждение с обоими написаниями;
  `POST …/name-ok` принимается лишь при действующем `close` для текущего ФИО (сверка повторяется на
  сервере; иначе 409); любая смена ФИО снимает подтверждение (возврат прежнего ФИО его не возвращает); в карточке и реестре сразу видно
  «ФИО подтверждено вручную: кто, когда»; запись в журнал с логином и написанием из реестра.
- `unknown` — предупреждение и окно «Добавить в реестр людей?» (ФИО, должность, ведомство — из карточки,
  правятся): запрос **из браузера** `POST /api/people {name, role, organization, document: «Объективка «ФИО»»,
  source: "profiles"}` под вошедшим человеком — пишет в реестр только человек. После добавления сверка повторяется.
- Портал не ответил (`failed`) — документ скачать можно, но **в пакет мероприятия без состоявшейся сверки
  файл не уходит** (`…/docx?package=1` → 409). В объединении сверяются и ФИО из прикреплённых файлов:
  расхождение показывается под результатом, такой файл в пакет не кладётся.

## Приложить к мероприятию (контракт п. 9)

Из браузера, same-origin, как «Бриф»: диалог со списком `GET /moderator/api/meetings` и
`GET /moderator/api/meetings?archived=true` (прошедшие «Совещание» само уводит в архив — без него их
не выбрать; так берёт «Повестка»), повторы по id склеиваются; сегодняшние и
будущие по возрастанию даты, потом прошедшие; «＋ Новое мероприятие»; запомненное в карточке отмечено,
но выбор всегда доступен) → `find-or-create` → папка по `link` «Материалов» (folder из «Совещания» —
подсказка; новый id — в «Совещание») → `POST /materials/api/events/{folder}/files` с
`source: {service: "profiles", id: "profile-<id>" | "merge-<id>"}` (объективок к мероприятию много —
source обязателен); 404 — одна перепривязка и повтор.
