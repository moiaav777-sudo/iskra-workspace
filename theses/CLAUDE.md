# Тезисы — чат сервиса

Этот чат отвечает только за папку `theses/`. Общие правила и контракт с порталом — в `../CLAUDE.md`,
задачи — в `../TRACK.md` → «Тезисы».

## Что делаем

Пятый сервис портала: **тезисы выступления под конкретного человека**.

Два способа получить тезисы:
1. **По теме.** Человек пишет тему своими словами и говорит, на сколько минут («тезисы о поддержке
   молодых педагогов, на 7 минут»). «Искра» пишет по правилам из файла правил.
2. **Из приложенных документов.** К теме прикладываются файлы (справка, доклад, письмо) — тезисы
   собираются из них, а не из общих знаний.
   Принимаются Word (.docx, .doc), Excel (.xlsx, .xls), PowerPoint (.pptx, .ppt), PDF, .rtf, .odt, .txt,
   .md, .csv — формат по содержимому, чтение общим модулем `app/docs_common.py` (копия `portal/shared`,
   здесь не править; решение пользователя 05.10).

Выход — **документ Word по формату из правил** и **вступительное слово для «Модератора»**
(кнопка «Отправить в Модератор»).

## Правила написания — главный документ

Пользователь даёт файл с правилами: что писать, как, где, что сверять, в каком формате выдавать.
Положите его в `docs/` и **считайте законом**: формат, длина, порядок частей, обращения, запреты —
всё оттуда. Если правила и ваша идея расходятся — правила сильнее, а расхождение опишите пользователю.

Правила зависят от того, для кого пишутся тезисы: под каждого человека может быть свой файл правил.
Заложите это сразу — выбор «для кого» при создании тезисов, правила подставляются по выбранному.

## Сверка фактов — как в «Брифе»

Числа и факты из приложенных документов проверяются по оригиналу и показываются с дословной цитатой.
Правило пространства (решение пользователя 19.09, подробности в `../SUMMARY-SPEC.md`):

- **неподтверждённое в документ не попадает**: пока есть непроверенные числа, выгрузка закрыта;
- **противоречие в самом источнике** подсвечивается жёлтым с пояснением — это не наша ошибка.

## Место в портале (уже выделено общим треком)

- id сервиса `theses`, адрес `/theses/`, порт **8960** на 127.0.0.1, `/healthz` обязателен.
- В портале сервис уже зарегистрирован с отметкой «в разработке»: плитку видит только администратор.
- На стенде поднимается сам, как только появится `theses/app/main.py`:
  `bash ../portal/scripts/dev_stack.sh` → http://127.0.0.1:8080/theses/ (вход `dev` / `dev-password-1`).
- Ключ «Искры» сервис не хранит: портал запишет его в `theses/.env` (`ISKRA_API_KEY`) при выкладке.
- nginx, туннель, задачу автозапуска, сторож и копии настраивает общий трек — напишите в `../TRACK.md`
  → «Запросы к общему треку», когда будете готовы к первой выкладке.

## Связь с «Модератором»

Тезисы нужны и отдельным документом, и как **вступительное слово** внутри брифа совещания.
Передача — из браузера пользователя, `credentials: 'same-origin'`, без общих секретов между сервисами
(так уже работает «Повестка» → «Модератор»):

- кнопка «Отправить в Модератор» у готовых тезисов;
- сначала выбор совещания (список берётся у «Модератора»), потом отправка;
- адрес на стороне «Модератора»: `POST /api/meetings/<id>/scenario/opening-from-theses`
  с телом `{"text": "…", "minutes": 7, "source": {"service": "theses", "id": "<id тезисов>"}}`;
  он кладёт текст во вступительное слово сценария. **Этот маршрут пишет чат «Модератора»** —
  общий трек передаст ему задание, как только формат тезисов устоится.
- папка пакета — через `link` «Материалов» по ключу совещания; `folder` из «Совещания» — подсказка (404 на загрузке — одна перепривязка и повтор; пользователь 02.10, скриншот A3).

## Правила

- Вход только из заголовков `X-Portal-*` с проверкой `PORTAL_SECRET`; своего входа и паролей нет.
- Администратор документы не ведёт: под `admin` создавать и править нельзя, ему остаются
  необратимые действия и настройки. Роль `chief` — только чтение.
- Адреса в интерфейсе относительные (`api/…`, `static/…`).
- Каждое изменение — в журнал портала (`POST /internal/audit`), по-русски и с «было → стало»;
  расход «Искры» — полями `tokens_in` / `tokens_out` в той же записи.
- `GET /api/search?q=&limit=` для общего поиска портала, `/theses/#new` — создать сразу.
- Реальные ФИО и документы в чат не выводить, тестировать на выдуманных данных.

## Нельзя

- Трогать `../portal`, `../moderator`, `../brief`, `../a3`, `../agenda`, VPS, туннель, задачи на ПК.
- Хранить в репозитории ключ «Искры», `.env` и рабочие данные.
- Выкладывать на боевой ПК: это делает только общий трек.
