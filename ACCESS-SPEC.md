# Кто что видит: иерархия и доступ к документу (19.09)

Решения пользователя от 19.09. До этого действовало правило «все видят и правят всё».

## Что меняется

1. **У сотрудника появляется непосредственный руководитель** — поле в портале, выбор из сотрудников.
2. **Списки документов показываются по кругу видимости:** свои → своего отдела (я и все, кто подо мной
   по цепочке) → все. Переключатель у списка, по умолчанию «мои».
3. **Это фильтр показа, а не запрет.** Выбрав «все», человек по-прежнему видит всё пространство —
   как было до сих пор. Настоящее разграничение доступа можно будет включить поверх готовой иерархии,
   если понадобится; решение пользователя — пока не запрещать.
4. **Накопленное раздаётся создателям.** Автор известен в каждом сервисе, поэтому старые документы
   попадают в круг «мои» к тому, кто их сделал. Документ без автора считается общим.

Не путать два разных «руководителя»:
- **роль `chief`** — «руководитель организации»: видит всё, не меняет ничего;
- **поле «непосредственный руководитель»** — иерархия между сотрудниками, влияет только на круг показа.

## Доступ к конкретному документу

У каждого документа в каждом сервисе — одинаковые возможности:

| Что | Кто может | Смысл |
|---|---|---|
| **Владелец** | создатель, может передать другому | отвечает за документ, единственный, кто удаляет навсегда |
| **Доступ «смотреть»** | владелец выдаёт | открыть, прочитать, скачать выгрузку; менять нельзя |
| **Доступ «работать»** | владелец выдаёт | менять наравне с владельцем; удалять навсегда и передавать владение — нет |
| **Виден руководителю** | автоматически | снять нельзя: руководитель видит работу своих людей |

Окно «Доступ» одинаковое во всех сервисах: владелец, список людей с уровнем, поиск сотрудника,
кнопка «Передать владение». Каждое изменение — в журнал портала: «Открыт доступ: Петров — работать»,
«Доступ закрыт: Петров», «Владелец: Иванов → Петрова».

## Что даёт портал сервисам

- **Заголовок `X-Portal-Team`** в проверке доступа: логины тех, кто под этим человеком по цепочке,
  через запятую (пусто — подчинённых нет). У роли `chief` и у администратора — `*`.
- **`GET /internal/users`** с общим секретом → `[{"login", "name", "active"}]` — список сотрудников
  для окна «Доступ» и для подписи «чьё это».

## Что делает сервис

- хранит у документа `owner` (уже есть везде: `owner` / `created_by` / `author`) и список доступа
  `[{login, level}]`, где `level` — `view` или `edit`;
- фильтрует список: **мои** (владелец я или мне выдан доступ) → **отдела** (владелец из `X-Portal-Team`)
  → **все**; выбранный режим запоминается у человека;
- показывает окно «Доступ» и пишет изменения в журнал;
- в общий поиск (`/api/search`) отдаёт документы всего пространства, но в поле `who` — владельца,
  чтобы человек понимал, чьё нашлось.

## Порядок работ

1. Портал: поле руководителя, круг видимости, `X-Portal-Team`, `/internal/users`, учёт круга
   в поиске, в «вы недавно работали» и в сводке. — общий трек.
2. Сервисы по очереди: фильтр списка и окно «Доступ». — чаты сервисов, по 1 дню каждый.
3. Проверка на стенде: два сотрудника и руководитель, совместная работа над одним документом.
