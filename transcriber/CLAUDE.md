# Транскрибатор

Сервис рабочего пространства workspace.example.ru. Заведён решением пользователя 27.09.2026, переделан
решением **02.10.2026**: транскрибатор — отдельный раздел, **распознаёт «Искра»** (не локальная модель),
на выходе три документа.

Правила этой папки — общий контракт `../CLAUDE.md` (роль чата, контракт сервиса с порталом, процесс
релиза, п. 5а — общие модули). Порт — 8980, адрес за nginx — `/transcriber/`.

## Задача (решение пользователя 02.10)

1. На странице — поле загрузки файла записи (общая зона `.dropzone`: «Перетащите сюда запись или
   нажмите, чтобы выбрать (аудио/видео до 500 МБ)») и кнопка **«Разобрать с Искрой»**.
2. Файл уходит в «Искру» по правилам её API (`../CLAUDE.md`, п. 5в; `app/engine/iskra_engine.py`):
   загрузка `/api/v1/chat/files` → **фоновый прогон** `POST /api/v1/runs` с `{id}` файла и
   `Idempotency-Key` → опрос `GET /api/v1/runs/{id}?after=N`. Синхронный `/api/v1/chat` для
   расшифровки не годится — ход ограничен 90 с. «Искра» делает **дословную транскрипцию**
   платформенной транскрибацией («слово в слово», абзацы с таймкодами `[ММ:СС]` и «Говорящий N:») и
   сохраняет её TXT-файлом в черновики разговора; файл приходит в `result.files: [{name,
   download_url}]` и скачивается с ключом (до 50 МБ). Файла нет — берётся `result.answer`.
   Прогон упёрся в 15 минут (или «сохранила в файл», а файла нет) — **один** повторный прогон в
   том же разговоре «отдай готовую расшифровку из черновиков текстовым файлом», без нового
   распознавания. Частями по «дальше» до `[КОНЕЦ]` — только запасной путь, если «Искра» вернула
   текст с `[ПРОДОЛЖЕНИЕ]` без файла. Общий срок ожидания — `ISKRA_DEADLINE` (40 мин).
3. По транскрипции «Искра» пишет **саммари** (`app/summarizer.py`) и **перечень поручений**
   (`app/orders.py`, строго JSON `{"orders":[{text, assignee, deadline}]}`, срок — только если назван).
4. На карточке записи три блока: «Транскрипция», «Саммари», «Перечень поручений» — каждый правится
   (с версией: правка не затирает «Искру» и другого человека) и скачивается в Word. Перечень —
   общим модулем `orders_docx.py` по эталону `moderator/docs/примеры/Перечень поручений 25.05.2026
   (пример).docx`; шапка и подпись — из полей карточки «Председатель» и «Должность».
5. **«Приложить к совещанию»** (решение пользователя 02.10): три документа уходят в «Совещание» на
   вкладку «Результаты» (`POST /moderator/api/meetings/{id}/results`, kinds transcript / summary /
   decisions) из браузера человека, как у «Брифа» и A3; в карточке — ссылка «Открыть совещание».

Долгая обработка — фоном с ходом дела и отменой (`app/jobs.py`), файл записи удаляется сразу после
разбора, содержимое в журнал не пишется (только факты и токены «Искры»).

## Общие модули (п. 5а) — править только в `portal/shared`

- `app/iskra_common.py` ← `portal/shared/iskra_common.py` (состояния прогона, расход токенов, тексты ошибок);
- `app/speech_common.py` ← `portal/shared/speech_common.py` (интерфейс `Engine`/`Segment`, резерв faster-whisper, подмена);
- `app/orders_docx.py` ← `portal/shared/orders_docx.py` (перечень поручений в Word по эталону; подключит и «Совещание»);
- `app/richtext_common.py` ← `portal/shared/richtext.py` (очистка и разбор HTML редактора блоков; тест
  `tests/test_blocks_format.py` сверяет копию байт в байт).

Копии раскладывает `portal/scripts/sync_shared.sh`; правка копии будет затёрта.

## Единый формат блоков (решение пользователя 13.10)

«Каждый раздел — отдельным блоком для форматирования, как в модераторе; единый формат; все делаем
одинаково». В карточке записи (`dialog#detail`) три документа — карточки общего компонента
`WorkspaceBlocks` (`portal/static/blocks.js` + `blocks.css`, Quill и DOMPurify из `/static/vendor/`,
отдаёт портал): «Транскрипция» (блок `draft`), «Саммари» (блок `summary`), «Перечень поручений»
(блок на поручение, `order-<id>`, поля «Ответственный» и «Срок»; несохранённое новое — `order-new`).
Корень один — `#doc-blocks` (`static/app.js` → `renderDocs`); ссылки «Скачать Word / текст» — в
подвале своей карточки (`footerHtml` компонента). Сохраняет блок сам, с версией документа (409 — сообщение, запись
перечитывается, редактор остаётся с набранным). Администратор и запись в работе у «Искры» — только
просмотр (`readOnly`; смена режима — `view.setReadOnly`, открытый редактор с правкой не закрывается).

- **Поручение — по id, не по номеру** (ревью RC-2026-10-13-2, К-1). Ключ `id` в JSON `orders` выдаёт
  сервер при записи перечня (`orders.ensure_ids`); правка его сохраняет; старые поручения без id
  получают при чтении «o1», «o2»… и записывают при первом сохранении. ✕ и «Добавить поручение» не
  выполняются, пока в другом блоке есть несохранённая правка (сообщение внизу окна). После 409
  редактор остаётся на том же поручении; если его тем временем убрали, блок остаётся с набранным,
  а «Сохранить» спрашивает, вернуть ли поручение в перечень, — поверх чужого не ложится.
- **Версия — с момента открытия редактора** (К-2): `onEditOpen` запоминает версию документа,
  перечитывание карточки (сведения, архив, конец пересборки) её не обновляет — чужая правка или
  новый результат «Искры» дают 409, а не затираются молча. После 409 берётся свежая версия.

- **Хранение.** Правка с оформлением приходит HTML (`PUT /text`, `/summary` — поле `html`; поручение —
  ключ `html`). Сервер чистит его всегда (`richtext_common.clean`, белый список общей панели) и
  выводит текст (`richtext_common.paragraphs`; абзацы транскрипции — через пустую строку, чтобы Word
  находил таймкод и говорящего). Таймкод в начале абзаца хранится `<span class="tc">` (серым в
  карточке и в Word): Quill этот класс снимает, поэтому сервер помечает его снова (`doc_html.mark_stamps`).
  Колонки `draft_html`, `summary_html`; текст рядом остаётся всегда —
  по нему работают «Искра», TXT, поиск и перечень в Word. Старый вызов с `text` работает как раньше.
- **HTML действителен, только если согласован с текстом** (Н-1): текст HTML (нормализованно по
  пробелам и тире) должен совпасть с хранимым текстом, иначе HTML не используется — правка на старом
  коде после отката не перекрывается устаревшим оформлением. Предел HTML правки — 1 000 000 знаков
  (`MAX_DOC_HTML`, 413), у поручения — 10 000 (оформление снимается).
- **Сброс.** Текст перезаписывает «Искра» (новая расшифровка, новое саммари, пересборка) — HTML
  сбрасывается в '', показывается свежий текст. Ответ «Искры» по поручениям html не несёт.
- **Карточка** отдаёт `draft_html`, `summary_html` и `html` у поручений: сохранённый или выведенный
  из текста (`app/doc_html.py`: таймкод `<span class="tc">`, говорящий `<b>`); `draft_styled` /
  `summary_styled` — есть ли правка с оформлением.
- **Word.** Транскрипция и саммари с оформлением — по `richtext_common.blocks`: жирный, курсив,
  подчёркнутый, зачёркнутый, цвет, заливка (в Word — жёлтое выделение, любой цвет заливки),
  заголовки полужирным крупнее, списки стилями «List Bullet»/«List Number», выравнивание. Абзац
  транскрипции без оформления (кроме полужирного говорящего) — как раньше, таймкод серым.
  **Не идёт в Word:** оформление поручений (перечень строится общим `orders_docx.py` по `text`, эталон
  не меняем), ссылки (только текст подчёркнутым синим), цитата (только отступ и курсив), цвет заливки
  (всегда жёлтый), нумерация «List Number» сквозная на весь документ (шаблон python-docx).
- **«Совещание»** (`/results`) получает сохранённый HTML, если он есть, иначе — как раньше.

## На что обратить внимание

- **Живой вызов расшифровки не проверен** (переделка 05.10 под правила API «Искры»): формы
  `POST/GET /runs` — из живой пробы с VPS 05.10, форма `files` в результате — из справки. Ждёт
  проверки пользователя короткой записью: включён ли инструмент транскрибации (включает
  администратор «Искры»; выключен — «Искра» скажет прямо, у нас это `NO_TRANSCRIPT`) и приходит ли TXT
  в `result.files`. Всё, что может прийти иначе (нет файла, иная форма `files`, ответ без пометок,
  отказ прозой), обработано защищённо — понятная ошибка, а не падение. Если «Искра» не примет аудио
  через API — вернуть вопрос Оркестратору (варианты — README).
- **Правила API «Искры»** (`../CLAUDE.md`, п. 5в): id файла одноразовый (повтор — новая загрузка или
  ход без файла), один разговор — один ход (409 — ждать), каждый ход ~51 тыс. входных токенов —
  лишних прогонов не делать.
- **Расход «Искры»**: расшифровка, саммари и перечень — по одному событию `/internal/audit` с
  `tokens_in/out` на каждый, включая отмену и ошибку (DEV-CHECKLIST, п. 4). Снятый прогон (отмена,
  срок, сбой опроса) — `DELETE` и его расход в `engine.spent`.
- **Контракт с порталом**: вход только по `X-Portal-*` с секретом, `/healthz`, относительные адреса,
  общая типографика (`base.css`, `workspace-header.js`). Своего входа, масштаба шрифта, реестров нет.
- **Администратор документы не ведёт**: интерфейс прячет загрузку и правку под `admin`.
- **DEV-CHECKLIST** (`../team/DEV-CHECKLIST.md`) — пройти перед «Готово к выкладке».

## Границы

Сервис не создаёт совещаний сам (просит «Совещание» через `find-or-create`), не пишет в реестр людей,
не кладёт файлы в «Материалы». Документы в «Совещание» кладёт браузер человека — только по кнопке.
