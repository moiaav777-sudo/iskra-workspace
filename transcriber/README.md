# Транскрибатор

Сервис рабочего пространства workspace.example.ru: запись разговора или совещания → «Искра» → три
документа: **дословная транскрипция**, **саммари**, **перечень поручений**. Каждый правится и
скачивается в Word; все три можно приложить к совещанию. Порт **8980** на 127.0.0.1, адрес за
nginx — `/transcriber/`.

История решений: 27.09 — сервис заведён, распознавание только локально (faster-whisper); 02.10 —
отложен (VPS 1 ядро / 2 ГБ не вытянет локальную модель); **02.10, вечер — решение пользователя:
распознаёт «Искра»**, отдельный раздел, три документа; затем — документы ложатся в «Совещание»
(вкладка «Результаты»).

## Как это работает

1. Человек перетаскивает запись в зону загрузки (или выбирает файл; аудио/видео до 500 МБ) и
   нажимает **«Разобрать с Искрой»**. Файл ложится во временную папку, ответ — сразу номер задания.
2. Фоном (`app/jobs.py`: очередь по одной записи, ход дела, время, «Отменить»):
   - **расшифровка** — `app/engine/iskra_engine.py`: файл уходит в «Искру», фоновый прогон
     `/api/v1/runs` расшифровывает его слово в слово с таймкодами и говорящими, текст приходит
     TXT-файлом из черновиков разговора;
   - **саммари** — `app/summarizer.py` (`/api/v1/runs` → опрос, как у A3 и «Брифа»);
   - **перечень поручений** — `app/orders.py` (тот же прогон, ответ строго JSON, проверка схемы).
   Транскрипция длиннее 120 тыс. знаков делится на части по абзацам: саммари каждой части и итоговое
   по ним, поручения — по частям с объединением без дублей. Середина ничего не теряет (раньше молча
   вырезалась); расход всех прогонов складывается.
   Файл записи удаляется сразу после расшифровки — успешной или нет.
3. Карточка записи: поля «Председатель», «Должность», «Дата совещания» (для шапки, подписи и имён
   файлов) и три блока — правка (с версией, `409` при чужой правке), «Скачать Word». «Пересобрать
   саммари и поручения» — заново по текущей (в том числе исправленной) транскрипции, без повторной
   расшифровки. Правка человека, сделанная пока «Искра» работала, не затирается.
4. **«Приложить к совещанию»** — см. ниже.

## Распознавание «Искрой»

По правилам API «Искры» (`../CLAUDE.md`, п. 5в; справка «Искры» и живая проба с VPS 05.10):
синхронный ход `/api/v1/chat` ограничен 90 с, фоновый прогон `/api/v1/runs` — 15 минутами.
Платформенная расшифровка идёт асинхронно, запись обрабатывается целиком (один файл — одна
расшифровка, до 500 МиБ и 3 часов), полный текст распознавания сохраняется TXT-файлом в черновики
разговора и приходит в результате прогона как `files: [{name, download_url}]` (у ключа есть `files:read`).

```
POST {ISKRA_URL}/api/v1/chat/files   multipart file, Authorization: Bearer <ISKRA_API_KEY>
     → {"files": [{"id": …}], "conversation_id": …}
POST {ISKRA_URL}/api/v1/runs         {"message", "instructions", "files": [{"id"}], "conversation_id"}
     Idempotency-Key: <на каждый прогон свой>
     → 202 {"run_id", "conversation_id", "status": "queued", "expires_at"}
GET  {ISKRA_URL}/api/v1/runs/{id}?after=N      (дальше — next_after), пауза 2→5 с, 429 — ждём
     → {"status": completed|failed|cancelled|interaction_required, "result": {answer, files, usage, …},
        "error", "events", "next_after"}
GET  {download_url}                  относительный — от ISKRA_URL, с ключом; до 50 МБ
```

- Файл до 500 МБ уходит **потоком** (multipart собирается кусками, `Content-Length` заранее) —
  в память целиком не ложится; отмена прерывает и загрузку.
- Просьба: «расшифруй с таймкодами и говорящими», дословно; абзацы по смене говорящего или каждые
  30–60 с, в начале абзаца `[ММ:СС]` и «Говорящий N:»; полный текст — TXT-файлом в черновики.
- **Основной путь — файл**: в `result.files` текстовый файл (`.txt`/`.md`; сначала тот, в имени
  которого «расшифровка»/«транскрипция») скачивается и разбирается. Ключ уходит только на адрес
  «Искры»: редиректы сам `urllib` не проходит (он переносил `Authorization` на новый хост), переходы
  (до 5) делает движок и на каждом шаге ставит ключ, только если адрес — хост «Искры»; срок — `TRANSCRIBER_ISKRA_DOWNLOAD_TIMEOUT` (300 с), предел — `TRANSCRIBER_ISKRA_RESULT_MAX_BYTES`
  (50 МБ). Файла нет — берётся `result.answer`.
- **Срок 15 минут**: прогон `failed` с кодом вроде `interrupted`/`timeout`/`expired` или дольше
  `TRANSCRIBER_ISKRA_RUN_LIMIT` (16 мин, наш прогон снимается `DELETE`) — один повторный прогон в том
  же разговоре: «отдай готовую расшифровку из черновиков целиком текстовым файлом» (без нового
  распознавания, файл записи не шлём — id одноразовый). То же, если «Искра» ответила «сохранила в
  файл», а файла в результате нет. Общий срок ожидания после загрузки — `TRANSCRIBER_ISKRA_DEADLINE`
  (40 мин: два прогона по 15 и запас).
- **Запасной путь**: файла нет, а в ответе текст с меткой `[ПРОДОЛЖЕНИЕ]` — «дальше» новым прогоном в
  той же `conversation_id`, пока не придёт `[КОНЕЦ]`, не больше `TRANSCRIBER_ISKRA_MAX_PARTS` (40)
  частей, повтор того же куска — остановка. Ответ без меток считается полным, но на карточке пометка
  ««Искра» не отметила конец расшифровки — проверьте, полна ли она».
- Таймкоды и говорящие разбираются в сегменты; таймкодов нет — сегменты по абзацам без времени.
  Маркеры списка перед таймкодом («- [00:05] …») снимаются, вступление («Вот расшифровка записи:»)
  и хвост («Если нужно, могу…») — тоже, по простым шаблонам и только строки без таймкода/говорящего.
- Строка хода дела — по состоянию и событиям прогона (`tool`/`content`): «в очереди», «распознаёт
  речь», «готовит текст», сколько прошло; текст событий никуда не пишется.
- Ошибки человеку: 401/403 — «ключ не настроен или неверен» (при скачивании — «нет права
  files:read»), 413 — «файл слишком большой для «Искры» (до 500 МБ)», таймаут — ««Искра» не
  ответила за N мин», файл результата больше предела — «больше 50 МБ». Отказ прозой («К сожалению,
  я не могу прослушать аудиофайл», «транскрибация отключена администратором») — только короткий
  ответ без таймкодов, говорящих и меток, о самой работе, который начинается как отказ (< 300 знаков)
  или несёт отказный признак — «отключена», «недоступен», «не удалось распознать», «невозможна»
  (< 400 знаков); короткая речь «Я не могу прийти завтра» —
  запись, а не отказ. В ошибку, журнал, заметку и лог идёт только код ситуации ««Искра» не вернула
  расшифровку» — текст ответа никогда. Без ключа сервис работает, разбор честно отвечает «Ключ
  «Искры» не настроен».
- Расход токенов — при любом исходе: у завершённого прогона из `result.usage`, у снятого (отмена,
  срок, сбой опроса, `interaction_required`) — после `DELETE` из его ответа или последнего состояния.

**Живой вызов не проверен** — формы `POST/GET /runs` взяты из живой пробы 05.10, форма `files` в
результате — из справки. Ждёт проверки пользователя короткой записью (1–2 мин): включён ли на
cloud инструмент транскрибации (его включает администратор «Искры»), приходит ли TXT в `result.files`.
Если «Искра» не примет аудио через API — вопрос Оркестратору; запасные пути: резервный движок
`whisper` (локально, нужна машина мощнее VPS) или разбиение записи на части.

`TRANSCRIBER_ENGINE` (`.env`): `iskra` — по умолчанию; `fake` — подмена для тестов и показа
(страница помечает «демонстрационный режим»); `whisper` — локальная faster-whisper, опциональный
резерв (`requirements-whisper.txt`, на сервере не ставится). Интерфейс один — `app/engine`
(`Engine.transcribe(path, cancelled) -> [Segment]`, общий модуль `speech_common.py`).

## Три документа в Word

- **Транскрипция** и **саммари** — `app/docx_export.py`: заголовок, название записи и дата, абзацы
  (в транскрипции таймкод серым, говорящий полужирным). Имена: «Транскрипция ДД.ММ.ГГГГ – <запись>.docx»,
  «Саммари ДД.ММ.ГГГГ – <запись>.docx».
- **Перечень поручений** — общий модуль `portal/shared/orders_docx.py` (копия `app/orders_docx.py`,
  раскладывает `portal/scripts/sync_shared.sh`; его же подключит «Совещание»), строго по эталону
  `moderator/docs/примеры/Перечень поручений 25.05.2026 (пример).docx`: A4 книжный, поля 20/15/20/20 мм,
  Times New Roman 16, межстрочный 1,15, красная строка 12,5 мм, по ширине (стиль «No Spacing»);
  шапка по центру полужирно в две строки — должность заглавными, черта и пустая строка под ней;
  «N. текст» одним абзацем, следом «Срок – до 25 июня 2026 г.»; **срока нет — строки «Срок» нет**;
  пустая строка между поручениями; три пустые строки и подпись «И.О. Фамилия» справа; названия и даты в теле нет; имя
  файла «Перечень поручений ДД.ММ.ГГГГ.docx»; только короткое тире. Должности нет — шапки нет;
  председателя нет — подписи нет. Пометку «ПРОЕКТ» из колонтитула эталона не воспроизводим.
- Дата в именах — «Дата совещания» из карточки, иначе день загрузки записи.

## Приложить к совещанию

Решение пользователя 02.10: результаты транскрибатора ложатся в «Совещание» (вкладка «Результаты»).
Кнопка на карточке разобранной записи видна только за порталом (на стенде без портала адресов
соседей нет). Окно: совещание из списка `GET /moderator/api/meetings` или новое — дата и название,
`POST /moderator/api/meetings/find-or-create`. Затем браузер (same-origin, под вошедшим человеком)
шлёт три запроса подряд:

```
POST /moderator/api/meetings/{id}/results
{"kind": "transcript" | "summary" | "decisions", "title": "Транскрипция совещания 25.05.2026",
 "html": "<p>…</p>", "text": "…", "docx_url": "/transcriber/api/records/{rec}/export/<transcript|summary|orders>.docx",
 "source": {"service": "transcriber", "id": "<id записи>", "url": "/transcriber/#record=<id>"}}
```

Тела готовит сервер (`GET api/records/{id}/results`, HTML экранирован; decisions — `<ol>` «текст
<br>Срок – …»), доставку — `static/meeting.js`. Повтор шлёт те же `source.id` — «Совещание» заменяет
документы того же вида. После отправки сервер запоминает совещание (`POST api/records/{id}/meeting`,
событие в журнале), на карточке — «Открыть совещание». Нет доступа к «Совещанию» (403) — понятный
текст, а не ошибка; «Совещание» ещё без `/results` (404) — «его нужно обновить». `docx_url` — обычный
адрес сервиса за порталом: без заголовков `X-Portal-*` отвечает 403, как всё остальное.

## Приватность записи

- Загруженный файл лежит в `TRANSCRIBER_UPLOADS` (по умолчанию `data/uploads/`) **только на время
  расшифровки** и удаляется сразу после — успешной или нет (`media.discard` в `finally`); при старте
  сервиса осиротевшие файлы удаляются (`media.clear_upload_dir`), зависшие записи помечаются ошибкой
  (`db.interrupt_stale`, в том числе новый шаг `ordering`).
- Запись уходит в «Искру» — это решение пользователя 02.10 (у «Искры» запись хранится по её правилам).
- В журнал портала уходят только факты (длительность, число знаков, число поручений, прогонов «Искры»,
  токены «Искры») — не текст транскрипции, саммари или поручений (проверяется тестами).
- Поиск портала (`GET /api/search`) ищет только по названию записи.

Документы хранятся в базе сервиса (`data/transcriber.db`, вне репозитория), пока запись не удалят
(сотрудник — в архив, администратор — насовсем).

## Журнал и расход «Искры»

Каждый прогон «Искры» — одно событие `/internal/audit` со своими `tokens_in/out`: «запись расшифрована»
(все прогоны расшифровки вместе, в том числе повторный и снятые), «саммари записи готово», «перечень поручений записи готов»; отмена и
ошибка на любом шаге — тоже одно событие со своим расходом. Скачивания, правки, сведения для документов
и приложение к совещанию — свои события без токенов.

## База

Колонки первой версии сохранены; новые (`summary_version`, `orders`, `orders_version`, `chair`,
`chair_role`, `meeting_date`, `meeting`) добавляются `ALTER TABLE` при старте. **Откат на первую
версию**: старый код новые колонки не читает, но записи, расшифрованные «Искрой» без таймкодов
(`start = null`), он не покажет (ошибка на `_stamp(None)`) — при откате такие записи удалить или
не открывать; записи в состоянии `ordering` старый код при перезапуске не снимает — пометить
ошибкой вручную (`UPDATE records SET state='error' WHERE state='ordering'`).

## Разработка

```
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt pytest httpx
.venv/bin/python -m pytest tests -q        # без сети, без «Искры»; node — для фронтенд-теста
cp .env.example .env                       # для стенда добавить TRANSCRIBER_DEV=1
TRANSCRIBER_DEV=1 TRANSCRIBER_ENGINE=fake \
  .venv/bin/python -m uvicorn app.main:app --port 8980   # → http://127.0.0.1:8980/
```

`TRANSCRIBER_DEV=1` подставляет пользователя `dev` с ролью `admin` и не проверяет секрет — только для
отдельного запуска без портала (кнопки «Приложить к совещанию» там нет).

## Что нужно от Оркестратора и сессии сервера при выкладке

1. **Юнит `work-transcriber`** на VPS (uvicorn `app.main:app`, `127.0.0.1:8980`, рабочая папка сервиса,
   `.venv` из `requirements.txt` — без faster-whisper), по образцу остальных `work-*`.
2. **Выкладка**: `transcriber` в белых списках `portal/ops/deploy-work.sh` и `.github/workflows/deploy.yml`
   (ревью RC-17, Н-1 — без этого выкладка не запустится); `KEY_TARGETS` в `portal/app/iskra_key.py`.
   **nginx**: `location /transcriber/` → `127.0.0.1:8980` со снятием префикса и заголовками `X-Portal-*`,
   как у соседей; **`client_max_body_size 510m`** (тело multipart чуть больше файла) (записи до 500 МБ) и **`proxy_read_timeout`/
   `proxy_request_buffering`** под долгую загрузку (как у `/materials/`).
3. **`ISKRA_API_KEY`** (и при необходимости `ISKRA_URL`) в `.env` сервиса — портал пишет ключ по
   списку сервисов, `transcriber` в этот список добавить; `PORTAL_SECRET` — тот же, что у портала.
4. **Права terra** на перезапуск `work-transcriber` (как у остальных юнитов).
5. **Карточка в портале** — `hidden: False` (сейчас скрыта), `ADMIN_WRITE_PATHS` для `transcriber` —
   только `DELETE /api/records/{id}`.
6. **«Совещание»**: `POST /moderator/api/meetings/{id}/results` по контракту выше (делает Оркестратор);
   до этого кнопка «Приложить к совещанию» честно говорит ««Совещание» этой версии так ещё не умеет».
7. **`portal/scripts/sync_shared.sh`** — добавлена раскладка `orders_docx.py` в `transcriber/app/`;
   общий модуль `portal/shared/orders_docx.py` новый — в кандидат вместе с сервисом.
8. Диск: временный файл записи до 500 МБ на время расшифровки (`data/uploads`), плюс временный файл
   разбора multipart у самого uvicorn — до ~1 ГБ свободного места на одну запись.
9. Первый живой разбор — короткой записью (1–2 мин): проверить, что «Искра» принимает аудио через
   `/api/v1/chat/files`, фоновый прогон отдаёт TXT расшифровки в `result.files` (инструмент
   транскрибации включён администратором «Искры»); посмотреть расход на вкладке «Искра».
