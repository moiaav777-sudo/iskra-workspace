# Настройка и донастройка

## 1. `.env` в корне (читает `run.sh` и docker compose)

| Переменная | Что это |
|---|---|
| `ISKRA_API_KEY` | ключ API «Искры». Пусто — ввести позже в портале |
| `ISKRA_URL` | адрес платформы, по умолчанию `https://cloud.iskrabot.ru` |
| `PORT`, `HOST` | порт и адрес шлюза (`0.0.0.0` в контейнере) |
| `PUBLIC_URL` | внешний адрес для писем сотрудникам |
| `ADMIN_LOGIN`, `ADMIN_PASSWORD` | администратор первого запуска; пустой пароль генерируется и записывается сюда |
| `PORTAL_SECRET`, `SECRET_KEY` | общий секрет шлюза и ключ подписи сессий; генерируются сами |

В контейнере файл настроек живёт в томе (`/app/data/.env`), чтобы пережить пересборку образа.

## 2. В портале, под администратором

- **Администрирование → Пользователи**: сотрудники, роли, доступы к сервисам, временные пароли,
  руководитель (иерархия), «выйти везде».
- **Администрирование → Искра**: ключ API и дата его окончания; портал раскладывает ключ по сервисам
  (`MODERATOR_DIR/.env`, `BRIEF_HOME/settings.json`, `A3_HOME/.env`, `THESES_HOME/.env`,
  `TRANSCRIBER_HOME/.env`, `PROFILES_HOME/.env`) и показывает, у кого он совпадает. Если ключ задан
  переменной окружения `ISKRA_API_KEY`, она главнее файлов.
- **Администрирование → Объявления**: сообщения сотрудникам в общей шапке (плановые работы, обновления).
- **Сводка**: расход «Искры» и активность по сервисам за месяц.
- Почта для временных паролей: `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM_NAME`,
  `SMTP_STARTTLS` в `.env` портала (`portal/.env`).

## 3. Переменные сервисов (их выставляет `run.sh`; на своём сервере — в юнитах или `.env` сервисов)

| Сервис | Переменные |
|---|---|
| Портал | `PORTAL_DATA` (база), `PORTAL_URL` (свой адрес для шлюза), `PORTAL_PUBLIC_URL`, `PORTAL_INSECURE_COOKIES=1` только без https |
| Совещание | данные в `moderator/data`; `MODERATOR_DIR` — где лежит его `.env` для ключа |
| Материалы | `MATERIALS_STORE` (дерево папок мероприятий), `MATERIALS_DATA` (кэш и служебное), `MATERIALS_HOME` |
| Бриф | `BRIEF_HOME` (результаты и `settings.json` с ключом), `BRIEF_PORT`, `BRIEF_NO_BROWSER=1`, `BRIEF_PAGES` |
| Инфографика A3 | `A3_KIT` (конструктор `a3/a3-kit.html`), `A3_DB`, `A3_HOME` |
| Тезисы | `THESES_DATA`, `THESES_HOME` |
| Транскрибатор | `TRANSCRIBER_HOME`, `TRANSCRIBER_ENGINE` (`iskra`; `whisper` — локальный резерв, ставится отдельно), пределы `TRANSCRIBER_MAX_BYTES`, `TRANSCRIBER_ISKRA_*` |
| Объективки | `PROFILES_HOME` |
| Общие | `DOCS_SOFFICE` (путь к LibreOffice, если он не в PATH), `DOCS_CONVERT_TIMEOUT` |

## 4. Поведение «Искры»: промпты и правила

Тексты, по которым работает ИИ, лежат рядом с кодом и правятся без программиста:
- «Бриф»: `brief/app/prompt.md`, `prompt_topic.md`, `prompt_summary.md`;
- «Инфографика A3»: `a3/a3-PROMPT.md` (правила листа) и `a3/skill/` (образец и справочники);
- «Совещание»: правила разбора материалов и сценария — `moderator/app/llm_extract.py` и соседние
  модули (схемы ответов проверяются кодом);
- «Тезисы»: правила конкретного человека хранятся в самом сервисе (раздел «Правила»);
- подсказчик портала: `portal/app/ask.py` (`RULES`, `KNOWLEDGE`).

После правки промптов перезапуск не всегда нужен: сервисы читают файлы при каждом вызове, где это
отмечено в их `CLAUDE.md`.

## 5. Состав сервисов и плитки портала

`portal/app/config.py` → `SERVICES`: имя, адрес, описание на плитке, кнопка «новое», плашка «новое,
проверяется», скрытые сервисы. `SERVICE_RUNTIME` — порты и папки данных. Новый сервис подключается
записью здесь, маршрутом в шлюзе (`dev_gateway.py` / nginx) и строкой в `ADMIN_WRITE_PATHS`, если
администратору нужны в нём необратимые действия.

## 6. Оформление

`bash portal/ops/apply_brand.sh iskra` или `default`. Тема — папка `portal/static/brand/themes/<тема>/`:
токены палитры и шрифта (`tokens.css`), знаки (`mark.svg`, `mark-dark.svg`, `wordmark.svg`,
`favicon.svg`), семейство Google Fonts (`fonts.txt`). Новая тема — новая папка по тому же образцу.
Остальные правила интерфейсов построены на токенах, поэтому меняются вместе с темой.

## 7. Свой сервер вместо `run.sh`

Каждый сервис — `uvicorn app.main:app --host 127.0.0.1 --port <порт>` из своей папки в своём `.venv`
(«Бриф» — `python app/server.py`), по systemd-юниту на сервис, перед ними nginx с `auth_request` —
образец в `deploy/nginx.example.conf` (замените домен, секрет и пути). Резервное копирование — копии
SQLite-баз и папок документов; все они перечислены в таблице переменных выше.
