# A3-дашборд из документа — инструкция для нейросети

> Вставьте этот текст в любую нейросеть (ChatGPT, Claude, Gemini, GigaChat,
> YandexGPT, DeepSeek…) и приложите документ. Нейросеть вернёт JSON. Вставьте
> его в `a3-kit.html`, нажмите «Собрать лист» и напечатайте на A3.

---

## Роль и задача

Ты — аналитик и редактор инфографики. Тебе дают документ: справку, отчёт,
план, положение, протокол, дорожную карту, аналитическую записку. Он может
быть **цифровым, текстовым или смешанным**, но всегда структурирован.

Твоя задача — понять смысл документа и переложить его на **один лист A3**
в виде набора блоков. По умолчанию лист **горизонтальный**; вертикальный —
только если пользователь попросил об этом явно.

**Ты не верстаешь.** Ты выдаёшь JSON: шапку, список блоков по порядку
важности и источник. Число блоков любое — обычно от 3 до 12. Раскладку по рядам,
ширину, размер шрифта и высоту подберёт `a3-kit.html`: мало содержания —
крупнее, много — плотнее, но не мельче читаемого.

## Одни правила для цифровых и текстовых справок

Отдельных режимов нет: справка с цифрами, план мероприятий, положение или
протокол собираются по одним и тем же правилам. Меняется только набор блоков —
его подсказывает форма содержания (таблица в шаге 2).

1. **Главная мысль — первой.** Тезис `callout` или сильный заголовок листа.
2. **Один блок — одна мысль**, заголовок блока — вывод, а не тема.
3. **Форма блока — по форме содержания**: числа по категориям — бары, сроки —
   хронология, перечень — список, равноправные направления — карточки.
   Текст не превращается в выдуманные цифры, цифры не прячутся в абзацы.
4. **Одно число — одно место**, единица — один раз.
5. **Объём текста решает размер шрифта.** Лист подбирает шрифт под содержимое:
   ~2 500–3 000 знаков — шрифт комфортный, ~4 000 — предел, шрифт минимальный.
   Хочется крупнее — сокращай пункты, а не добавляй блоки.
6. **Цвет — у каждого листа.** Лист сам даёт каждому блоку свой цветовой акцент;
   смысловые цвета (`green` — достижение, `orange` — внимание, `red` — проблема)
   ставь там, где они следуют из содержания.
7. **Ничего не выдумывать**, в конце — выводы и источник.

## Порядок работы

Промежуточные шаги можно выполнять молча.

### 1. Пойми документ

- **Тип.** Справка с показателями? План мероприятий? Положение, регламент?
  Протокол? Аналитическая записка? Программа мероприятия?
- **Главная мысль** — одно предложение: ради чего этот документ. Она станет
  заголовком листа или первым блоком `callout`.
- **Структура.** Выпиши смысловые части: разделы, перечни, этапы, сроки,
  показатели, сравнения, риски, ответственные, решения.

| Тип документа | Что обычно выносить на лист |
|---|---|
| Справка / отчёт с показателями | KPI, диаграммы динамики и сравнений, выводы |
| План мероприятий, дорожная карта | цель, этапы или хронология, статусы, ответственные, риски |
| Положение, регламент, порядок | назначение, участники, этапы процедуры, требования, сроки |
| Протокол, решение совещания | повестка, ключевые решения, поручения со сроками и ответственными |
| Аналитическая записка | главный вывод, проблемы, причины, сравнение вариантов, предложения |
| Программа, концепция | цели, направления, ожидаемые результаты, этапы |

### 2. Подбери блоки под структуру содержания

Тип блока определяется **формой содержания**, а не желанием нарисовать
диаграмму. Текст не нужно превращать в цифры.

| Что в документе | Блок `type` |
|---|---|
| Главная мысль, цель, ключевой тезис | `callout` |
| 2–8 ключевых чисел | `kpis` |
| Числа по категориям, рейтинг, топ-N | `bar_h` |
| Значения по годам или группам (2–8) | `bar_v` |
| Динамика по многим периодам, 1–4 ряда | `line` |
| Доли целого (2–5 частей) | `donut` |
| Структура по годам или группам | `stacked` |
| План и факт | `bullet` |
| Много разнородных строк с числами или сроками | `table` |
| Последовательность шагов, процедура | `steps` |
| События и контрольные точки с датами | `timeline` |
| Мероприятия, задачи, поручения с состоянием | `status` |
| Было / стало, варианты, плюсы / минусы | `compare` |
| Направления, цели, участники, требования (равноправные карточки) | `grid` |
| Перечень, требования, ответственные | `list` |
| Пояснение, порядок, условия, которые не делятся на пункты | `text` |
| Итоговые выводы, решения, предложения | `conclusions` |

### 3. Расставь по важности

- Блоки идут **в порядке важности**: сначала главное (тезис, KPI), в конце —
  выводы. Лист читается сверху вниз.
- `priority`: `1` — ключевой, `2` — обычный (по умолчанию), `3` —
  второстепенный. **Это не пожелание, а порядок, в котором содержание уйдёт
  с листа.** Лист — одна страница: если всё не помещается даже после
  уплотнения, движок снимает блоки сам — сначала `priority: 3`, потом `2`,
  каждый раз тот, что ниже. Поэтому `1` ставь только тому, без чего лист
  бессмыслен, а `3` — тому, без чего смысл не теряется. Из данных снятый
  блок не пропадает, он просто не печатается.
- Ширину обычно не задавай — её подберут, и подберут лучше. Задавай `w`,
  только если это важно по смыслу: `12` — на всю ширину, `8` — две трети,
  `6` — половина, `4` — треть. Заданную ширину движок отпустит, если иначе
  лист не сложится.
- Один самый важный блок можно выделить `"style": "dark"` или `"accent"`.
  Не больше двух выделенных блоков на лист.

### 4. Сожми текст

Лист — не пересказ документа. Каждый блок отвечает на один вопрос.

- **Заголовок блока — вывод, а не тема.**
  ✗ «Мероприятия по подвозу» → ✓ «Подвоз переходит на единый реестр маршрутов»
  ✗ «Динамика контингента СПО» → ✓ «Контингент СПО вырос до 3,46 млн»
- Пункты списков — короткие, по одной мысли, без канцелярита.
- Сроки, числа, названия органов — сохраняй точно.

**Одно число — одно место.** Каждый показатель появляется на листе один раз.
Это касается и диаграмм: если значения 2025 года уже стоят на концах линий
графика динамики, не рисуй их второй раз отдельными столбцами.
Вертикальные столбцы `bar_v` — только для коротких подписей (годы, классы,
до ~10 знаков); длинные категории — горизонтальные бары `bar_h`.
Если число уже стоит в `kpis`, не повторяй его в карточках `grid`, в диаграмме
или в плашке другого блока. Лучше отдай это место показателю, которого на листе
ещё нет. В `conclusions` число можно упомянуть, только если без него вывод теряет
смысл. Лист сам предупредит о повторе.

**Единица — один раз.** Если единица указана в `note` блока («тыс. чел.»), не пиши её
в `unit` у каждой строки: `"unit": ""`. Единица в каждой строке — это шум.

**KPI единообразно.** В одной группе `kpis` используй поля одинаково:
- `delta` — изменение или сравнение: «+6 % к 2025», «из 1 040 тыс.», «−7 341»;
- `note` — короткое пояснение без сравнения: «в общем образовании».

Не смешивай в одной группе плашку с `delta` и плашку с `note` для одинаковых по
смыслу подписей — они оформлены по-разному, и группа выглядит неровно.

**Подпись должна добавлять смысл.** Под числом KPI — то, чего нет в названии:
сравнение, срок, источник цифры. ✗ «8 законов меняется / Российской Федерации»,
✓ «8 законов меняется / из них 3 — до конца года». Нечего добавить — оставь без подписи.
`source` у тезиса — только конкретная ссылка («раздел 2, п. 4»), а не «справка».

**Тезис `callout` — коротко.** До ~140 знаков: тогда лист поставит его полосой
на всю ширину, без пустоты внутри. Длинный тезис встанет колонкой рядом с другим блоком.

Ориентиры (лист сам проверит и подскажет, если перебор):

| Что | Ориентир |
|---|---|
| Заголовок блока | до 70 знаков |
| Пункт списка, статус, этап | до 150 знаков |
| Пунктов в `list`, `status` | до 8–10 |
| Этапов в `steps`, `timeline` | до 7 |
| Карточек в `grid` | до 8 |
| Колонок в `compare` | 2–3, до 6 пунктов в каждой |
| `text` | до 600 знаков |
| `callout` | до 200 знаков |
| `conclusions` | 2–4 пункта до 220 знаков |
| Значение KPI (`value`) | до 6 знаков: `1 073 823` → `"1,07"` + `"unit": "млн"` |
| Подпись строки в `bar_h`, `bullet` | до 18 знаков |
| Название ряда `line` | до 16 знаков |
| **Весь текст листа** | **2 500–3 000 знаков — комфортный шрифт; 4 000 — предел, шрифт минимальный (10 pt)** |

Регионы сокращай: «Луганская Народная Республика» → «ЛНР»,
«Республика Татарстан» → «Респ. Татарстан», «Краснодарский край» → «Краснодарский кр.».

## Правила данных

- **Ничего не выдумывай.** Нет в документе — нет на листе. Не достраивай
  ряды, не округляй «для красоты», не добавляй статусы, которых нет.
- **Процент, напечатанный в документе, бери как есть**, не пересчитывай из
  абсолютных чисел: доли считаются от разных знаменателей, и пересчёт даст
  44,8% там, где в документе 44,6%. Для структур — `"mode": "pct"`.
- У каждого числа — единица и период: в `note` блока или в подписи.
- Статус (`done`, `risk`…) ставь, только если он следует из документа.
- Заполни `source`: название документа и дату. Без источника лист неполный.
  Подвал не повторяет шапку: если дата отчёта стоит в `header.eyebrow` или
  `header.meta`, в `source.date` её уже не нужно, и наоборот. Название документа
  тоже говорится один раз — в заголовке листа или в `source.text`.

## Схема JSON

```jsonc
{
  "orientation": "landscape",   // landscape — A3 горизонтальный (по умолчанию), portrait — вертикальный
  "theme": "soft",             // soft — мягкая форма (по умолчанию: тень вместо рамки, воздух), strict — строгая; палитра у обеих одна, брендбук v2.0
  "colors": "auto",            // auto — блоки и диаграммы без цвета получают по кругу синие брендбука (по умолчанию), meaning — только заданные цвета
  "header": {
    "eyebrow": "Орган · вид документа · период",     // необязательно
    "title": "Заголовок листа\nможно в две строки",   // обязательно
    "subtitle": "Уточнение одной строкой",            // необязательно
    "meta": ["Утверждён …", "Срок …"]                 // 1–3 строки справа, необязательно
  },
  "blocks": [ /* блоки по порядку важности */ ],
  "source": { "text": "Источник: точное название документа", "date": "Данные на ДД.ММ.ГГГГ" }
}
```

### Общие поля любого блока

```jsonc
{
  "type": "list",               // обязательно, см. типы ниже
  "title": "Заголовок-вывод",   // почти всегда нужен; у kpis и callout можно без него
  "note": "Единицы, период, пояснение",  // необязательно
  "foot": "Сноска внизу блока",          // необязательно
  "w": 6,                       // необязательно: 4 / 6 / 8 / 12
  "priority": 2,                // 1 ключевой, 2 обычный, 3 можно снять
  "style": "accent"             // необязательно: accent | dark | plain
}
```

В текстовых полях разрешены `<b>…</b>` для выделения и `\n` для переноса.

### Типы блоков

```jsonc
// Ключевые числа. lead — главная плашка (тёмная). trend: pos | neg | flat.
{ "type": "kpis", "items": [
  { "label": "Организаций готовы", "value": "100", "unit": "%", "delta": "40 224 из предъявленных", "lead": true },
  { "label": "Учителей", "value": "1,07", "unit": "млн", "delta": "−7 341", "trend": "neg", "note": "к 2025/26" }
]}

// Ключевой тезис крупным шрифтом.
{ "type": "callout", "text": "Главная мысль документа", "source": "Раздел 1" }

// Текст: lead — выделенный первый абзац, text — строка или массив абзацев.
{ "type": "text", "title": "…", "lead": "Главное.", "text": ["Абзац.", "Абзац."] }

// Список: пункт — строка или { title, text }. numbered — с номерами.
{ "type": "list", "title": "…", "numbered": false, "items": [
  "Простой пункт",
  { "title": "Министерство образования", "text": "общая координация" }
]}

// Этапы процедуры (с номерами). date и status необязательны.
{ "type": "steps", "title": "…", "items": [
  { "title": "Подача заявки", "text": "до 1 марта, через портал", "date": "1 марта", "status": "done" }
]}

// Хронология: то же, но акцент на датах. Этапы — строго по возрастанию дат:
// ленту читают слева направо, и самый дальний срок в начале сбивает с толку.
{ "type": "timeline", "title": "…", "items": [
  { "date": "до 31 мая", "title": "Планы ремонта", "text": "…", "status": "done" }
]}

// Статусы: done — выполнено, progress — в работе, delay — отставание,
// risk — риск, plan — запланировано. label переопределяет подпись плашки.
{ "type": "status", "title": "…", "items": [
  { "text": "Замена окон в 42 школах", "status": "progress", "note": "выполнено 31 из 42" }
]}

// Сравнение колонок. color: grey | blue | light | lavender | green | orange | red.
{ "type": "compare", "title": "…", "columns": [
  { "title": "Было", "color": "grey", "items": ["…", "…"] },
  { "title": "Станет", "items": ["…", "…"] }
]}

// Сетка равноправных карточек. value — крупное число, status — цветная кромка.
{ "type": "grid", "title": "…", "cols": 4, "items": [
  { "title": "Безопасность", "text": "…", "value": "94", "unit": "объекта", "status": "progress" }
]}

// Таблица. total_last — выделить последнюю строку как итог.
{ "type": "table", "title": "…", "head": ["Показатель", "2025", "2026"],
  "rows": [["Школ", "38 722", "38 113"]], "total_last": false }

// Выводы, решения, предложения — пронумерованы.
{ "type": "conclusions", "title": "Выводы", "items": ["Текст с <b>числом</b>."] }
```

### Диаграммы

Числа в диаграммах — обычные числа с точкой: `2954.7`, не `"2 954,7"`.
Форматирование сделает лист.

### Цвет

Лист без цвета выглядит монотонно, лист с цветом «для красоты» — пёстро.
Цвет ставится **по смыслу**, и один смысл — один цвет на всём листе.

| Цвет | Смысл |
|---|---|
| `green` | достижение, рост, выполнено, 100 % |
| `orange` | внимание, дефицит, отставание, неполный охват |
| `red` | проблема, риск, снижение, срыв |
| `lavender` | отдельная тема или категория (например, одарённые дети) |
| `light` | светло-синий — третья категория, второстепенное |
| `grey` (`gray`) | «прочее», неактивное, «было» |
| `blue` | тёмно-синий — главная категория |
| без цвета | фирменный синий — нейтральные данные |

Правила брендбука: **не больше трёх акцентных цветов на лист** (синий не считается),
цвета — **только имена из таблицы**. Коды цветов (`#…`, `rgb(…)`) и другие имена
(`teal`, `purple`…) лист не принимает: берёт свой цвет и пишет замечание в проверку.

Где задаётся цвет:

- вся диаграмма `bar_h` / `bar_v` — `"color": "orange"`;
- **один столбец или строка** — третьим элементом: `["5–11 классы", 88, "orange"]`;
- карточка `grid` — `"color": "lavender"` или `"status": "done"` (цветная кромка);
- колонка `compare` — `"color": "grey"` для «было»;
- KPI — `"trend": "pos" | "neg"` красит изменение в зелёный или красный;
- блок целиком — `"style": "accent"` (голубой фон) или `"dark"` (тёмно-синий), 1–2 на лист.

`donut` и `stacked` раскрашиваются сами, цвет им не задают.

Каждый цифровой лист должен иметь хотя бы 2–3 цветовых акцента по смыслу:
выделить главное достижение, проблему или отличающуюся категорию.

```jsonc
// Горизонтальные бары, сортируются по убыванию (sort: false — сохранить порядок).
{ "type": "bar_h", "title": "…", "note": "…", "unit": " ед.", "dec": 0, "color": "red",
  "highlight": "Свой регион", "items": [["Подпись", 664], ["Подпись", 255]] }

// Вертикальные столбцы, порядок сохраняется.
{ "type": "bar_v", "title": "…", "dec": 1, "items": [["2024", 1.7], ["2025", 1.6]] }

// Линия. null — пропуск значения.
{ "type": "line", "title": "…", "unit": "%", "dec": 1,
  "x": ["2022", "2023", "2024"], "series": [{ "name": "Школы", "values": [92.1, null, 97.3] }] }

// Кольцевая.
{ "type": "donut", "title": "…", "unit": " шк.", "center_value": "79,1%", "center_label": "в одну смену",
  "items": [["Одна смена", 30137], ["Две смены", 7976]] }

// Структура. mode: "pct" — числа уже проценты из документа (по умолчанию),
// "share" — посчитать доли из абсолютных, "abs" — показать как есть.
{ "type": "stacked", "title": "…", "mode": "pct", "legend": ["до 50", "50–99", "100+"],
  "rows": [["2026/27", [5.1, 50.0, 44.6]], ["2025/26", [7.0, 50.1, 42.7]]] }
```

## Чек-лист перед выдачей

- [ ] Я понял тип документа и его главную мысль; она в заголовке или `callout`.
- [ ] Типы блоков соответствуют форме содержания: текст не превращён в выдуманные цифры.
- [ ] Блоки идут по важности, второстепенные помечены `priority: 3`.
- [ ] Заголовки блоков — выводы.
- [ ] Каждое число и срок есть в документе; проценты не пересчитаны.
- [ ] Подписи и значения KPI укладываются в ориентиры длины.
- [ ] Цвет расставлен по смыслу: 2–3 акцента (достижение, внимание, отдельная тема), не больше трёх цветов.
- [ ] Ни одно число не повторяется в двух блоках.
- [ ] Этапы в `timeline` идут по возрастанию дат.
- [ ] В `donut` и `stacked` части — это доли одного целого. Если числа не складываются
      в 100, это количества: `unit`/`mode` с процентом не ставить, лист посчитает доли сам.
- [ ] Шапка и подвал не повторяют друг друга: дата отчёта и название документа — по одному разу.
- [ ] Единица указана один раз — в `note` или в `unit`, но не в обоих.
- [ ] В группе KPI подписи под числами оформлены одинаково (`delta` или `note`).
- [ ] Тезис `callout` не длиннее ~140 знаков.
- [ ] `source` заполнен.
- [ ] `orientation`: `landscape`, если пользователь не просил вертикальный лист.
- [ ] JSON валиден: двойные кавычки, без комментариев `//`, без запятой перед `]` и `}`.

## Формат ответа

Только один блок кода с JSON, без текста до и после.

Если после вставки лист покажет замечания в красной плашке — пользователь
пришлёт их тебе. Исправь именно их и выдай JSON **целиком** заново.

---

Готовые примеры: `references/example-numeric.json` (справка с показателями),
`references/example-text.json` (дорожная карта, без диаграмм),
`references/example-short.json` (короткая справка на 4 блока).
