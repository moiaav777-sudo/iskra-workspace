# Библиотека листов A3

Сервис вокруг конструктора `a3-kit.html`: загрузили справку — «Искра» собрала лист,
проверка вёрстки прошла сама, лист открылся в предпросмотре, его можно поправить руками,
скачать или сохранить в библиотеку.

## Путь справки

1. `POST api/spark/draft` — файл (Word, Excel, PowerPoint, PDF, RTF, ODT, текст — формат по
   содержимому, `app/docs_common.py`) или вставленный текст.
   Текст справки уходит в «Искру» с правилами из `a3-PROMPT.md` и **на сервере не сохраняется**.
   Ответ — `202` и номер разбора, а не готовый лист: разбор идёт минутами.
2. Браузер спрашивает о ходе дела через `GET api/spark/jobs/{id}`: очередь, работа,
   готовый лист или понятная ошибка. «Искра» возвращает JSON листа по схеме
   `spark.SHEET_SCHEMA`, лист попадает в библиотеку.
3. Браузер открывает `editor?id=…&autofix=1`, движок рисует лист и выдаёт замечания самопроверки.
4. Если замечания есть, они уходят обратно в «Искру» (`POST api/sheets/{id}/spark/fix` — тоже
   `202` и номер разбора), приходит исправленный JSON, лист перерисовывается. Кругов — не
   больше двух, дальше сервис честно говорит: «поправьте вручную».
5. Человек правит лист руками (режим правки в конструкторе), сохраняет, скачивает HTML
   или печатает в PDF из браузера.

Проверка вёрстки живёт в браузере, в `a3.js` — поэтому круг исправления замыкается на клиенте,
Chrome на сервере не нужен.

## Очередь разборов

Обращения к «Искре» идут фоном и по одному за раз (`app/jobs.py`): «Искра» на один ключ ведёт
один прогон, а держать минутное соединение не даст ни браузер, ни шлюз портала. Поэтому:

- запрос только ставит работу в очередь, обрыв связи и перезагрузка вкладки её не отменяют;
- человек видит, сколько разборов впереди и сколько времени идёт его собственный;
- в очередь берём не больше восьми справок, дальше — `429` с человеческим текстом;
- пока круг идёт, лист отмечается живым, иначе список через шесть минут сочтёт круг брошенным;
- сервис перезапустили — номер разбора теряется, о чём страница и говорит: лист мог успеть
  сохраниться, его видно в библиотеке.

Расход токенов «Искры» копится у листа: и разбор справки, и каждый круг доработки, в том числе
неудачный прогон и повтор без схемы. Он виден в карточке списка и уходит в журнал портала.

## Библиотека

- Версия растёт при каждом сохранении, в истории видно, кто и когда менял.
- Одновременная правка ловится по номеру версии: второй сохраняющий получает 409 и имя того,
  кто успел раньше.
- Сотруднику доступен архив, удаление насовсем — только `admin` (контракт портала, п. 2).
- Скачанный файл самодостаточен: открывается без сервиса и без интернета.

## Контракт с порталом

Вход только по заголовкам `X-Portal-User/Role/Name` при верном `X-Portal-Secret`,
адреса относительные, изменяющие запросы с чужим `Origin` отклоняются,
каждое изменение уходит в `POST /internal/audit` с «было → стало», `GET /healthz` без входа.

## Запуск стенда

```
python3 -m venv service/.venv
service/.venv/bin/pip install -r service/requirements.txt
cp service/.env.example service/.env      # для стенда добавить A3_DEV=1
A3_DEV=1 service/.venv/bin/python -m uvicorn app.main:app --app-dir service --port 8940
```

`A3_DEV=1` подставляет пользователя `dev` с ролью `admin` и не проверяет секрет — только для стенда.

Тесты: `service/.venv/bin/python -m pytest service/tests` (без сети, «Искра» подменяется).
