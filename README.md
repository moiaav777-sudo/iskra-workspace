# Рабочее пространство

Единое рабочее место сотрудника аппарата: один вход, семь сервисов, каждый отдаёт готовый документ.
Разбор документов, подготовка текстов и распознавание речи — через API «Искры».

Срез для передачи «Искре» от 11.10.2026 (исходный коммит `d92dc8d`). Оформление — по бренд-листу «Искры»
(тема переключается, см. [docs/CONFIGURATION.md](docs/CONFIGURATION.md)).

## Запуск за пять минут

Нужны Linux или macOS и Python 3.11+ (лучше 3.12). Docker не обязателен.

```bash
git clone <адрес этого репозитория> workspace && cd workspace
cp .env.example .env            # впишите ISKRA_API_KEY; можно оставить пустым и ввести ключ позже в портале
./run.sh
```

Через минуту-две скрипт напечатает адрес (`http://127.0.0.1:8080`). Входы стенда (из `.env`, меняются там же):
**admin / admin** — административная часть (люди, доступы, ключ «Искры», журнал, сводка; документы администратор
не правит), **user / user** — пользовательская часть (все семь сервисов). Данные лежат в `./data`,
остановка — Ctrl+C, повторный запуск — тот же `./run.sh`.

То же в контейнере (образ тяжёлый из-за LibreOffice и ffmpeg, они нужны для перевода старых форматов
и для записей; без них всё остальное работает):

```bash
cp .env.example .env
docker compose up -d --build
```

Контейнерный запуск собран по тому же `run.sh` и проверен только синтаксически: в окружении, где
готовился срез, не было демона Docker. Запуск через `./run.sh` проверен целиком, включая все страницы.

### Прямо в GitHub, без своего сервера (Codespaces)

На странице репозитория: **Code → Codespaces → Create codespace on main**. GitHub соберёт окружение
(`.devcontainer/devcontainer.json` ставит зависимости сам), дальше в терминале Codespace:

```bash
cp .env.example .env     # ключ «Искры» — по желанию, можно ввести потом в портале
./run.sh
```

GitHub пробросит порт 8080 и откроет адрес вида `https://<имя>-8080.app.github.dev`. Входы те же:
admin / admin и user / user. Это удобно, чтобы посмотреть продукт; для постоянной работы нужен
свой сервер или контейнер.

## Что внутри

| Сервис | Адрес | Что отдаёт |
|---|---|---|
| Портал | `/` | вход, пользователи и их доступы, журнал действий, ключ «Искры», сводка по работе, «Спросить Искру» |
| Совещание | `/moderator/` | повестка, участники, материалы к вопросам (разбор «Искрой»), документ ведущего, поручения, результаты; пакет совещания одним нажатием |
| Папка мероприятия («Материалы») | `/materials/` | документы к мероприятию в одной папке с закреплённой нумерацией, реестр, приёмная с телефона, пакет архивом |
| Бриф | `/brief/` | бриф по региону / теме / сводный по справке в Word, с проверкой цифр по источнику |
| Инфографика A3 | `/a3/` | лист A3 по справке: «Искра» собирает, проверка вёрстки сама, правка руками, печать |
| Тезисы | `/theses/` | тезисы выступления по теме или документам, по правилам конкретного человека; в Word и во вступительное слово совещания |
| Транскрибатор | `/transcriber/` | запись совещания → расшифровка, саммари, перечень поручений (распознаёт «Искра») |
| Объективки | `/profiles/` | объективка на человека по имени (открытые источники) или по справке; объединение в один файл |

Сервисы связаны между собой: материалы и документы уходят в папку мероприятия, тезисы — во вступительное
слово, результаты «Транскрибатора» — в совещание. Подробнее — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## «Искра»

Все обращения к ИИ идут через API «Искры» (`cloud.iskrabot.ru`, ключ с правами `chat:run`, `skills:run`,
`web_search`, `files:write`, `files:read`). Короткие вопросы — синхронным чатом, разборы документов,
тезисы и расшифровки — фоновыми прогонами с опросом результата (у чата предел 90 секунд). Ключ один на
все сервисы: администратор вводит его в портале, портал раскладывает его по сервисам и следит за
сроком действия. Ключ в репозиторий не входит.

## Как устроен запуск

`run.sh` поднимает каждый сервис отдельным процессом на `127.0.0.1` и перед ними шлюз на одном порту.
Шлюз делает то же, что на боевом делает nginx: перед запросом к сервису спрашивает портал, кто вошёл,
и передаёт сервису проверенного пользователя заголовками `X-Portal-*` с общим секретом. Образец боевой
конфигурации nginx — [deploy/nginx.example.conf](deploy/nginx.example.conf).

## Тесты

У каждого сервиса свои тесты (`pytest`, у интерфейсов — проверки в node). Все вместе — около 1400 тестов:

```bash
cd portal && .venv/bin/python -m pytest -q        # и так же в moderator, materials, theses, transcriber, profiles, a3/service
```

Окружения `.venv` создаёт `./run.sh --install`; для тестов нужны ещё `requirements-dev.txt` там, где они есть.
